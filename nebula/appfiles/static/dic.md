## 一、认识词库

> 编写 `.n` 词库脚本时应遵守的约定，目的是保持词库可读、可维护、可复用。

### 文件规范

- 词库脚本统一使用 `.n` 后缀；对外输出网页的 Web 词库使用 `.wn` 后缀。
- 文件统一使用 UTF-8 编码。
- 按用途放入对应目录：
  - `private/` 资源目录：存放重要资源与词库；
  - `public/` 词库目录：公开可访问；
  - `database/` 储存目录：数据读写；
  - 机器人词库放 `<账号路径>/dic/`，仅 `.n` 后缀会被执行，其余后缀（`.md`/`.txt`/`.json` 等）自动跳过，可放心存放说明文档。
- 建议按功能拆分文件，避免把大量触发词堆在单个文件。

### 触发词规范

- 触发词独占一行，正文紧跟其下；**正文必须连续书写，不能出现空行**（空行会结束当前词条，之后的正文会被当作新触发词导致脱离词块），详见「换行规则 → 词条层」。
- 入口触发词 `Main` 只在**需要「无参数主动执行」的默认入口**时使用（网页被访问 / 定时任务 / `$执行词库$` 等主动执行场景），用于展示首页 / 默认内容。
- **功能 / 娱乐类词库（五子棋、钓鱼、签到等）不要写 `Main`**：这类词库靠用户发消息触发词唤起（如「五子棋」「钓鱼」「下子 A1」），机器人收到消息是精确/正则匹配触发词执行，**永远轮不到 `Main`**。写了 `Main` 是死代码，还容易让 AI 把使用说明、菜单等不该展示的内容塞进去。
```
✗ 错误：功能词库不需要 Main（Main 里内容永远不会被机器人触发）
Main
使用说明：输入「五子棋」开始...

五子棋
...

✓ 正确：功能词库直接写各功能触发词，无 Main
五子棋
...

下子 (.+)
...

棋盘
...
```
- **机器人场景下 `Main` 不是消息兜底入口**：机器人收到用户消息是按消息文本精确/正则匹配触发词的，匹配不到就不会回复，**不会落到 `Main`**。因此不要把「菜单」「帮助」等内容写在 `Main` 下面——机器人的菜单由管理端配置（`$设置菜单$` 等菜单函数），用户点击菜单项后通过 `[菜单事件]<功能ID>` 触发词唤醒对应词条（见「六、内置函数 → QQ机器人 → 菜单 / 指令面板」）。
- 普通触发词用简短明确的文字；需要模糊匹配时使用正则，如 `测试 .+`。
- 匹配文本按空格分割可用 `%参数0%`、`%参数1%` 读取；正则捕获组可用 `%括号0%`（整体）、`%括号1%`（第一组）读取。
- 定义函数用 `[函数]名称`（可加参数规则 `[函数|1|2]名称`），定义内部回调用 `[内部]名称`（用 `$回调 名称$` 触发）。
- **触发词正文里可以直接 `$函数名$` 调用 `[函数]` 定义的函数**（多个触发词复用同一段逻辑的正规做法，如 `背包` / `渔获` 触发词都写 `$显示背包$`）。函数定义可以放在文件任意位置——**在触发词后面定义同样有效**（实测），只要函数名精确匹配。
- 特殊触发用 `[类别]触发词` 定义，其中 `类别` 为任意自定义名称（如 `[按钮事件]同意`），由对应事件框架主动派发。
- **机器人词库建议写导航指令触发词**：`菜单`、`功能`、`帮助` 等，让用户发消息即可查看可用功能与用法。它们就是普通触发词，正文直接输出即可，**不需要也不应该写进 `Main`**。`菜单`、`功能`、`帮助` **本就是同一类导航触发词**，按需选一个即可（**一般推荐用 `菜单`**），不要三个都写导致重复。其中 `菜单` 正文要**逐个列出各功能的触发指令**（告诉用户发什么指令能唤起对应功能），而不是只写功能名：
```
菜单
可用功能：\r
五子棋 —— 发送「五子棋」开始\r
钓鱼   —— 发送「钓鱼」开始\r
签到   —— 发送「签到」领取

功能
可用功能：五子棋 / 钓鱼 / 签到 / 帮助

帮助
发送「菜单」查看功能列表；发送具体功能词即可开始使用
```
> 上面示例同时列出 `菜单`/`功能`/`帮助` 仅为演示三种写法，实际任选其一即可（一般用 `菜单`）。
> 多行列表要在每行行尾加 `\r` 换行（最后一行不加），否则正文行会直接拼接成一行，见「换行规则 → 输出层」。
> 这里的「菜单」是词库里的**文字导航触发词**；机器人还有一套管理端配置的「快捷菜单」（`$设置菜单$` 下发、点击走 `[菜单事件]<功能ID>`），两者不冲突，见「六、内置函数 → QQ机器人 → 菜单 / 指令面板」。

### 书写风格

- 变量赋值用 `键:值`，读取用 `%键%`。
- 调用函数用 `$函数名 参数1 参数2$`。
- 注释用 `//`（单行）或 `/* */`（多行）。
- 正文建议统一缩进（4 空格），判断/循环/函数框等块结构内尤其要保持一致。
- 参数含空格时用 `"..."` 包裹为一个整体。
- 多行内容优先用结构化写法：`文本>...<文本`、`JSON>...<JSON`、`变量:函数>...<函数`、`<?n ... ?>`（或 `#{ ... }#`），避免依赖裸换行。

### 引入指令规范

- `#引入=` 是预编译指令，必须放在词库文件头部。
- 引入本地文件：`#引入=dic/a.n`；引入整个目录：`#引入=dic/*`。
- 引入机器人函数：`#引入=@QQBot`、`#引入=@NapCat` 等，可多行引入多个。
- 引入文件并返回实例包：`变量:#引入=目标`。

### 资源指令规范

- `//@资源` 是编译期指令，写法为 `//@资源` 单独占一行，下一行写 `变量名:文件路径`，把文件内容读入变量，之后用 `%变量名%` 引用：
  ```
  //@资源
  文件数据:文件路径
  ```
- 文件路径相对**应用数据目录**（`private/`，与 `#引入=` 一致）解析（也支持绝对路径）。
- 当 `//@资源` 指向 `.n` 后缀的路径时，会自动把该词库编译为 gob 字节（`[]byte`）存入变量，可直接传给 `$创建服务器$` 复用；含自定义函数无法序列化时回退为原始文本。
- 资源在编译期读入并随编译结果缓存；文件内容变化后需重新编译（保存/加载词库）才会更新。
- `//@一次性资源` 用法与 `//@资源` 完全相同，区别是变量**读取一次后即销毁**：首次 `%变量名%` 读到内容，之后该变量视为未定义（渲染为 `%变量名%`），适用于只需读取一次的敏感数据或临时内容：
  ```
  //@一次性资源
  一次性数据:文件路径
  ```

### 变量命名规范

- 变量名、触发词、函数名使用有意义的中文或英文。
- 避免使用下划线 `_` 开头结尾的命名，该形式保留给系统魔术变量（如 `%__词库路径__%`、`%_继承_%`）。
- 变量名（键名）长度最多 32 字节（按 UTF-8 字节计，中文一个汉字占 3 字节），超出该长度将无法被识别为赋值变量。

### 注意事项

- 循环框留空为死循环（`循环>i`），务必在循环体内提供 `>终止` 或 `>终止循环` 退出条件。
- 机器人主动发送函数需先在头部 `#引入=@机器人`；回复函数由消息框架自动注入，无需引入。
- **机器人场景下，词库正文直接输出的文本就会自动作为回复发送**：触发词下面的普通文本行、`文本>` 块、`%变量%` 拼出来的内容，执行后都会自动回复给发消息的人，**不需要**再用 `$发送文本 ...$` 这类函数。`$发送文本$` / `$发送MD$` 等回复函数只在「主动再补发一条消息」（如回复一条之后又发一条额外内容）时才用。
- 输出网页内容时，记得用 `$全局变量 输出类型 ...$` 或 `$设置头部 ...$` 设置正确的 Content-Type。
- 存储简单键值数据**优先用常用读写函数** `$读 路径 键 默认值$` / `$写 路径 键 数据$`（写入 `database/` 目录文件），不要动辄使用全局数据库 `db_*`；`db_*` 只用于余额、排行、多账号等关系型数据场景。路径按「游戏/功能 → 分类 → 用户」分层，**推荐用 `<游戏名>/<分类>/<QQ>.txt`（不加群号，跨群共享用户数据）**，文件名保持简短，多拆文件夹分类、一个文件夹下尽量全是文件，详见「六、内置函数 → 文件操作 → 储存习惯与路径组织」。
- `$GET$` / `$POST$` 只适用于**HTTP 网页词库**被访问时；**机器人词库**中读取用户消息请用 `%参数N%` / `%括号N%` / `%QQ%` 等消息变量，不能用 `$GET$` / `$POST$`。
- JSON 嵌套取值在 `%...%` 里用 `%@变量.键.键%`（点分隔，数组用数字索引），**不要用** `%变量[索引]%`、`%变量.[索引]%`、`%变量->键%`（都不解析）；`->` 只用于赋值快捷解析 / `$JSON解析` 批量解析 / 函数变量传出 / `JSON>` 框多层键。构建 JSON：`变量:{`/`变量:[` 写原样 JSON（`%变量%` 必须带引号）；或 `JSON>变量={}`/`JSON>[]` 按 `键=值` 构建（行尾不能带逗号，嵌数组/数字用 `键:=值`），见「六、内置函数 → JSON 操作」。
- **文本块（`文本>`、三引号文本框）内 `$函数$` 不会执行**，会原样输出字面 `$函数$`；`变量:{`/`变量:[` 原样 JSON 块内残留 `$...$` 是非法 JSON，会让整块返回 error。需要函数结果先 `变量:$函数$` 存起来，再在块内用 `%变量%` 引用。
- **函数体内的赋值默认是函数局部**，不声明 `->变量` 传出则外部读不到、也不会覆盖外部同名变量；需要函数计算结果带回外部时，在定义处写 `[函数]名称->变量1,变量2`。
- **变量名在赋值时裸写，不要带 `%`**：赋值写 `随机数:$随机数 1 100$`，读取才写 `%随机数%`。写成 `%随机数%:...` 不会被当作赋值，整行当普通文本输出、变量也没赋上（实测）。
- **函数参数里、算术表达式 `[...]` 里都不能再嵌套 `$函数$`**：`$JSON存 %背包% 草鱼 %$JSON解析 ...$ + 1$`、`$延迟 [1000*$随机数 1 3$]$` 都是错误写法（实测前者输出乱文、后者报参数错误）。正确做法：先 `旧数量:$JSON解析 %背包% 草鱼$`、`秒:$随机数 1 3$` 拿到中间值，再 `$JSON存 %背包% 草鱼 $计算 %旧数量% + 1$$`、`$延迟 [1000*%秒%]$`。
- **块开启行（`如果>`、`循环>`、`文本>` 等）行尾不要跟 `//` 注释**：条件会被注释内容干扰导致判断失效（实测 `如果>$JSON判断 %背包%$ // 非空` 不命中、去掉注释才正常）。注释单独写一行。

### 换行规则

词库中「换行」涉及多个层面，各自独立，写多行内容前先分清指哪一层。

#### 词条层（最重要）：正文中不能出现空行

触发词独占一行，它下面的正文行必须连续书写，**正文中不能插入空行**：

- 空行会**立即结束当前词条**：空行前的行组成一个词条，空行后的行会被当作**新的触发词**重新开始。因此正文里夹空行会导致代码脱离原词块——后半段变成无人匹配的"新触发词"，整个功能静默失效。
- 词条与词条之间用空行分隔是正常写法；注释行 `//` 不打断词条，可以放心使用。

```
✗ 错误：正文中夹了空行，会被拆成两个词条
Main
你好

再见

✓ 正确：正文连续书写
Main
你好
再见
```

- 块结构（`如果>/<如果`、`循环>/<循环`、`文本>/<文本`、`变量:函数>/<函数` 等）**内部同样不能有空行**，空行会把块从中截断。
- **块结构的开启行之前、闭合行之后也不能加空行**（实测）：`如果>...<如果` 闭合后紧跟空行，会把空行后的代码拆成新触发词、不再执行；开启行前加空行则整个块脱离触发词。判断框、循环框等上下都应紧贴正文书写：
```
✗ 错误：判断框闭合后加了空行，「尾」被拆成新触发词不再执行
钓鱼
如果>%a%==1
ok
<如果

尾                       // 变成新触发词「尾」，永远执行不到

✓ 正确：判断框上下紧贴正文
钓鱼
如果>%a%==1
ok
<如果
尾
```
- **正文内禁止空行，即使是用 `//` 注释做分段标题也不行**：一个触发词的正文必须从头到尾**连续书写**。AI 生成时最常见的错误是：给每个逻辑段落写一行 `//` 注释当小标题，并在注释前后加空行分隔——这些空行会立即结束词条，把后续代码拆成无人触发的新词条。`//` 注释本身不打断词条、可以保留，但**注释必须紧贴前后代码，前后都不加空行**；多个 `如果>` / `循环>` 块之间也要连续书写，块闭合行（如 `<如果`）之后直接接下一段：
```
✗ 不推荐：块之间用「空行 + // 注释」分段
下子 (.+)
坐标:%括号1%
如果>%棋盘%=={}
    >终止
<如果

// 解析坐标
字母:$取前字符 1 %坐标%$
...

✓ 推荐：全文连续，// 注释紧贴前后代码、不加空行
下子 (.+)
坐标:%括号1%
如果>%棋盘%=={}
    >终止
<如果
// 解析坐标
字母:$取前字符 1 %坐标%$
...
```
- 唯一例外：`<?n ... ?>` / `#{ ... }#` 多行块内部允许空行（空行会作为代码行保留）。

#### 文件层：换行符与行切分

- 文件统一按行解析，用 `\n`（LF）换行即可；Windows 的 `\r\n`（CRLF）也完全兼容——每行行尾的 `\r` 会被自动去掉。
- 文件末尾的换行不会产生多余空行。

#### 输出层：正文行之间不会自动换行

普通正文行执行后的输出是**直接拼接**的，行与行之间不会自动插入换行：

```
Main
a
b
```

输出是 `ab`，而非 `a\nb`。

只需要单行输出时，直接写成一行即可，能不加换行就不加：

```
Main
你好
```

输出正好是 `你好`（行首行尾都没有多余换行）。只有当确实需要换行时才用下面的方式显式指定：

- 行尾写 `\r`：该行输出结尾变为真实换行 `\n`（如 `a\r` 输出 `a\n`）。**只对「正文输出行」生效**。
- **多行输出时最后一行不要加 `\r`**：中间行用 `\r` 换行、最后一行结尾留空即可，否则输出末尾会多出一个空行（实测 `第一行\r` + `第二行\r` 输出 `第一行\n第二行\n`，多了行尾 `\n`）。正确写法：
```
Main
第一行\r
第二行\r
第三行      // 最后一行无 \r
```
输出为 `第一行\n第二行\n第三行`（末尾无多余换行）。
- **赋值行（`变量:...`）里的 `\r` 不会被转义**，会按字面 `\r` 存进变量（实测 `内容:第一行\r` 再 `%内容%` 输出的是字面 `\r` 两个字符）。需要给变量拼多行文本时用 `%换行%` 拼接：`内容:%内容%%鱼名% x %数量%%换行%`，不要用行尾 `\r`。
- 魔术变量 `%换行%`：值为一个真实换行 `\n`，可嵌入任意插值位置（赋值行、正文行、块内行都有效）。
- `$函数 "..."$` 成对引号内的 `\n` 转义（见「双引号包裹参数」）。

#### 多行块层：块内行的拼接规则

- `文本>` / `纯文本>` 框：内容行之间**不会自动换行**，行与行用什么连接由**开启行后缀**决定（后缀会做 `%变量%` 插值）：
  - `文本>`（无后缀）：行间无分隔符，内容直接拼接；
  - `文本>%换行%`：行间以换行连接，结果直接输出；
  - `文本>变量=%换行%`：`=` 左侧为赋值目标变量，拼接结果赋给变量（无输出）；
  - 拼接结果末尾不加分隔符。
- `变量:"""` / `变量:'''` 框：内容行以 `\n` 连接后赋值给变量（`"""` 做 `%变量%` 插值，`'''` 内容原样）。
- `JSON>` 框：内容行是 `键=值` / `键:=值` 设置项而非裸文本，行间不拼接换行。
- `<?n ... ?>` / `#{ ... }#`：块内每一行作为独立词库行逐行展开执行，用于把一段词库代码横跨多行书写（空行即空语句）；它改变的是**代码排版**，不会自动给输出加换行。

> 结论：多行内容不要依赖「裸换行」产生换行效果。要输出换行请用 `\r` 后缀、`%换行%` 或块开启行后缀显式指定；要跨行写词库代码请用 `<?n ?>` / `#{ }#`。

#### 赋予值

都支持多字符赋予值文本
```
:$: 执行函数
: 支持多字符，特殊功能
+: 拼接跟加值
-: 减少数值
:: 绝对文本赋予值

```

> **赋予值支持转义**（仅 `:` 普通赋值，值中的 `\r` 直接表示换行，`\\` 表示字面反斜杠，故 `\\r` 表示字面 `\r`，`\:` 表示字面冒号）：
> ```
> a:a\rb      // a = a<换行>b
> a:a\\rb     // a = a\rb（字面反斜杠 + r，不换行）
> a:名\:值     // a = 名:值
> ```
> 不带转义时值按原样处理（`a:abc` 仍是 `abc`）。`::` 是**绝对文本赋予值**（不执行 `$函数$`、`%变量%`，**不支持转义**，值原样写入）。

> **正文行一旦以「名字+半角冒号 `:`」开头（如 `状态:进行中`），就会被解析成赋予值**：把 `状态` 赋值为 `进行中`，**该行不输出**（实测输出为空，但 `%状态%` 能读到值）。因此**不要用带半角冒号的文本行当输出/说明**。
> 需要输出带冒号的内容时：
> - 用**全角冒号 `：`**：`状态：进行中` → 原样输出（半角 `:` 才是赋值符，全角不是）；
> - 或写 `\:` 转义半角冒号：`状态\:进行中` → 输出 `状态:进行中`，`\:` 不会被当作赋予值、直接转成 `:` 输出；
> - 或放进 `文本>` 块内（块内行原样输出，`状态:进行中` 照常显示）；
> - 仅作说明文字用 `//` 注释，不参与输出。

##### 反取示例

```
a:false?:错误
%a%
```

```
a:@"{"a":"null"}"->a?:没有数据
%a%
```

> **`?:` 只在赋予值中生效，支持「回退」与「三目」两种写法**：
> - **回退/兜底**：`变量:值?:回退值`，当 `值` 为 `false`/`null`/空时取 `回退值`。
> - **三目**：`变量:条件?真值:假值`，条件为真取 `真值`，否则取 `假值`。
>
> **优先级（解析顺序）**：
> - 先看第一个 `?`：`?` 后面**紧跟** `:`（即 `?:`）→ 按「回退」切分；`?` 后面不是 `:` 且其后还有 `:` → 按「三目」处理。
> - 三目命中后只按「第一个 `?` + 其后第一个 `:`」切分 `条件 / 真值 / 假值`，**假值部分即使再含 `?:` 也不会二次解析**。
> - 回退命中后，按 `?:` 切分出的各段**不再二次解析三目**；`@json` 路径只在回退段内以 `@` 前缀识别。
>
> 两者都**不能**内嵌在正文输出或 `%变量%` 里——例如 `（$判断空值 %昵称%$?游客:%昵称%）` 直接写在正文里是语法错误。要按条件二选一输出，先把结果算进变量，再 `%变量%` 输出：
```
✗ 错误：三目表达式内嵌在正文里
欢迎 $判断空值 %昵称%$?游客:%昵称%。

✓ 正确：三目条件用判断函数，写进赋予值再输出变量
称呼:$判断空值 %昵称%$?游客:%昵称%
欢迎 %称呼%。
```

#### 数值计算精度边界

词库数值核心采用 `int64 + float64`，编写脚本时需注意以下精度边界：

- 整数变量直存 `int64`，范围 `-2^63 ~ 2^63-1`（约 `±9.22e18`）。
- 整数运算（`+:` / `-:` / `*:`）溢出 `int64` 后会回退为 `float64`，而 `float64` 只能精确表示绝对值不超过 `2^53`（约 `9.01e15`）的整数，超出后低位会被静默丢弃。
- 除法（`/:`）结果恒为 `float64`。
- 当前**不支持任意精度（无上限）整数计算**；如需超出上述范围的精确整数运算，请自行拆解或改用其他方案。

> **条件整体连写，运算符与操作数之间不要加空格**（尤其是 `&`/`|` 两侧）：条件解析按字符切分，`%a%<0 | %a%>=15` 这类留空格写法会把空格吞进操作数、数值比较退化成字符串比较，导致结果错误（实测同一条件随 a 值不同给出错误分支）。比较符（`==`、`!=`、`>=` 等）两侧的空格在简单单条件里能识别，但混用时同样有风险，稳妥写法一律连写：

> 如果>%列索引%<0|%列索引%>=15|%行索引%<0|%行索引%>=15

> `!` 有两种用法：放在条件前面（如 `!a==b`、`!(a==b)`）表示对整个条件取反；放在两个值中间（如 `a!b`）表示长度判断（len(a)==len(b)）。

> **`如果:` 与 `如果>` 是两种不同的判断，关键字不能混用：**
>
> - `如果:条件` = **行内判断**：分支用 `否则` / `否则如果:条件`，结尾用 `如果尾`；`如果尾` 之后的语句继续执行（自动结尾）。若省略 `如果尾`，则 `否则` 之后的内容延续到词条末尾。支持多行逻辑。
> - `如果>条件` = **判断框**：分支用 `>否则` / `>否则如果:条件`，闭合用 `<如果`（不带 `>`）；支持多行逻辑、可嵌套。
>
> 两者都能承载多行逻辑，差别在关键字风格：`如果:` 用不带 `>` 的 `否则` / `否则如果:`，以 `如果尾` 结尾；`如果>` 用带 `>` 的 `>否则` / `>否则如果:`，以 `<如果` 闭合。**不能交叉混用**（`如果:` 配 `<如果`、或 `如果>` 配 `否则`/`如果尾` 都无效）。
>
> 错误示范（`如果:` 却用 `<如果` 闭合，`<如果` 会被当普通文本输出）：
> ```
> 如果:$JSON存在 %背包% 草鱼$
>     旧数量:1
> 否则
>     旧数量:0
> <如果                         // 如果: 的结尾是 如果尾，不是 <如果
> ```
> 上面应把 `<如果` 改为 `如果尾`，或改用判断框 `如果>$JSON存在 %背包% 草鱼$` + `>否则` + `<如果`。

#### 判断框

```
如果>a==a
ok
>否则
no
<如果
```

> **判断框闭合标签是 `<如果`，不带 `>`**；写成 `<如果>` 是错误写法，不会被识别为闭合。
> 分支关键字带 `>` 前缀：`>否则`、`>否则如果:条件`（对应行内判断的 `否则`、`否则如果:`），不要漏写。
>
> **漏写 `>` 前缀的后果（实测）**：分支行会退化成普通行——`否则如果:%随机%<=80` 被当作**赋值行**（变量 `否则如果` 得到字面值，不输出）、后面的行被当普通行继续执行、`否则` 被当**普通文本原样输出**，分支逻辑完全失效。例如：
> ```
> 如果>%随机%<=50
>     鱼:鲫鱼
> 否则如果:%随机%<=80     // 漏写 > ：不是分支，是赋值行
>     鱼:草鱼
> 否则                    // 漏写 > ：不是分支，是普通文本
>     鱼:金龙鱼
> <如果
> ```
> 实测（条件 `%随机%<=50` 为真）：`鱼` 被一路覆盖成 `金龙鱼`，`否则` 两个字还会被**当普通文本输出**，分支没生效。必须写成 `>否则如果:%随机%<=80`、`>否则`。

> **`>否则` 与 `>否则如果:` 的用法**：
> - `>否则如果:条件` = **多分支判断**（else if）：当 `如果>` 以及之前的 `>否则如果:` 都不满足时，再判断这个条件；命中就执行该分支，执行完**跳出判断框**，不再匹配后面的分支。冒号后**紧跟条件**，如 `>否则如果:%x%==2`。
> - `>否则` = **兜底分支**（else）：前面所有条件都不满足时执行；**不带条件**，必须放在所有 `>否则如果:` 之后（可选，只在需要兜底时写最后）。
> - 分支从上到下依次匹配，命中第一个满足的分支后即停止。
> ```
> 如果>%x%==1
>     一
> >否则如果:%x%==2
>     二
> >否则如果:%x%==3
>     三
> >否则
>     其他
> <如果
> ```
> 结果：`%x%==1` 时输出 `一`，`%x%==2` 时输出 `二`，`%x%==3` 时输出 `三`，都不满足时输出 `其他`。

> **判断条件支持中文逻辑连接词**：`或` / `或者` = 逻辑或（等价 `|`），`且` / `并且` = 逻辑与（等价 `&`），可与符号混用，支持括号分组：
> ```
> 如果>%状态%=={} 或 %状态%==null       // 中文「或」= |
> 如果>%状态%=={} 且 %状态%!=null       // 中文「且」= &
> 如果>%x%==1 并且 %y%==2 或者 %z%==3   // 可混用
> 如果>%x%==9 或 (%x%==1 且 %y%==2)     // 括号分组
> ```
> 连接词**前后必须有空格包裹**（写成 ` 或 `、` 且 `）；不带空格的中文字按普通文本参与比较（如 `%s%==黑或白` 是字面比较，不会拆分）。

> **判断条件支持中文比较运算符**：`等于` = `==`、`不等于` = `!=`、`大于` = `>`、`小于` = `<`、`大于等于` = `>=`、`小于等于` = `<=`，可与符号、中文逻辑连接词混用：
> ```
> 如果>%x% 等于 1 或 %x% 等于 2                // 等于 = ==，或 = |
> 如果>%状态% 不等于 null 且 %状态% 不等于 {}    // 不等于 = !=，且 = &
> 如果>%分数% 大于等于 60                      // 大于等于 = >=
> ```
> 中文比较运算符**前后也必须有空格包裹**（写成 ` 等于 `、` 大于等于 `）；不带空格的中文字按普通文本参与比较（如 `%s%==等于` 是字面比较，不会拆分）。

**支持套娃判断**
```
如果>a==b
    ok
>否则如果:a==a
    如果>a==a
        ok
    >否则
        no
    <如果
<如果
```

支持两种判断内方法
```
>跳过
>终止
```

#### 匹配（switch）

`匹配>` 框对**同一个值/表达式**做多路等值匹配，等价于一串 `如果>%x%==值` + `>否则如果:`，但主体表达式只求值一次（记住变量），写法更简洁。

```
匹配>%分数%
如果是:90
    优秀
如果是:60
    及格
如果不是
    不及格
<匹配
```

- 开启：`匹配>表达式`（`%变量%` / `[算术]` / `$函数$`，主体**只求值一次**）
- 分支：`如果是:值`，做**等值比较**（等价 `如果>` 的 `==`，字符串相等）
- 兜底：`如果不是`（必须放在所有 case 之后，可选）
- 闭合：`<匹配`（不带 `>`）

> 从上到下匹配，命中第一个 case 后执行其正文并**跳出匹配框，不穿透**；都不命中且写了 `如果不是` 则执行兜底，没写则什么都不做。
> case 值同样支持 `%变量%` / `$函数$` 动态求值（与主体一致），但仍只做**等值**匹配，不支持区间/正则/多值（需要这些用 `如果>`）。

```
匹配>%状态%
如果是:1
    正常
如果是:2
    维护中
如果是:%其他状态%
    命中动态 case 值
如果不是
    未知
<匹配
```

> 框内支持 `>跳过`（跳出匹配框）与 `>终止`，可嵌套。
> `如果不是` 是保留的兜底关键字；要匹配字面量 `不是` 需写成 `如果是:不是`。

#### 通用判断（判断）

`$判断$` 对一段**空格区分的条件表达式**求值，返回 `true` / `false`，用于把「是否满足条件」存成变量或作为三目 `?:` 的条件。

```
$判断 a 等于 a 或 true$
$判断 %分数% 大于等于 60$
$判断 %x% 等于 1 且 %y% 等于 2$
$判断 1 等于 2 或 (%x% 等于 1 且 %y% 等于 2)$
```

| 写法 | 含义 |
| ---- | ---- |
| `等于` / `==` | 相等 |
| `不等于` / `!=` | 不相等 |
| `大于` / `>` | 大于 |
| `小于` / `<` | 小于 |
| `大于等于` / `>=` | 大于等于 |
| `小于等于` / `<=` | 小于等于 |
| `或` / `或者` / `\|` | 逻辑或 |
| `且` / `并且` / `&` | 逻辑与 |
| `()` / `!` | 括号分组 / 取反 |

> 参数以**空格**区分：`$判断 a 等于 a 或 true$` 会被拆成 `判断`、`a`、`等于`、`a`、`或`、`true`，再作为条件表达式解析求值。
> 中文比较/逻辑词**前后必须有空格**（` 等于 `、` 或 `），与 `如果>` 规则一致；无空格的中文按普通文本参与比较。
> 操作数中的 `%变量%` / `[算术]` 按**逐个操作数**求值（与 `如果>` 一致），因此变量值里即使含判断符号（如 `==`、`>`、`或`）或空格也不会被误拆，会作为整体参与比较。

#### 循环框

`循环>变量=次数`：`=` 符号用于赋予循环次数（字面量整数或 `%变量%`/`$函数$` 动态表达式），循环变量从 1 开始递增到次数后结束；省略 `=`（`循环>变量`）则为死循环，需用 `>终止`/`>终止循环` 退出。

`循环>变量=起始~结束`：用 `~` 分隔起始值与结束值，循环变量从起始值递增到结束值（含两端），起止值同样支持 `%变量%`/`$函数$` 动态求值；起始值大于结束值为空范围（不执行循环体）。

> 循环变量默认从 1 开始，因此 `循环>i=1~5` 与 `循环>i=5` 完全等价；普通「循环 N 次」直接写 `循环>i=N` 即可，无需写 `1~N`。

```

%i%
<循环
```

更方便的循环

```

留空死循环

>终止循环

```

内部可以放在触发下

成功
```

> 类内置回调：在类中定义 `[内部:类名]名称`，类方法内部用 `$回调 名称$` 触发（仅在类实例内生效）。

```

```
Main

$甲.回调 内部名$
```

**回调触发词支持正则**，捕获组进 `%括号N%`（N 从 1 开始）；`$回调` 后的空格分隔参数进 `%参数N%`，`%触发词%` 为完整调用文本：

```
Main
$回调 坐标转行列 A1$
%行% %列%          // 输出：0 1

[内部]坐标转行列 (.+)
文本:%括号1%        // 正则捕获：A1
字母:$取前字符 1 %文本%$
列:$查找字 ABCDEFGHIJKLMNO %字母%$   // 1
数字:$截取 %文本% 1 999$
行:$计算 %数字% - 1$
%行% %列%           // 回调输出 "0 1"，调用方用 变量:$回调 ...$ 捕获
```

**变量互通**：回调内可直接读取调用方的所有变量（上面的 `%触发词%`、`%括号1%` 即来自调用方上下文）；但回调内对变量的赋值**只在回调内生效，不会回传调用方**（与 `[函数]` 的 `->变量` 传出机制不同）。调用方想要回调的计算结果，只能通过**回调的输出文本**配合 `变量:$回调 名称 ...$` 捕获：

```
Main
棋盘:{...}
胜者:$回调 检查胜负 %@棋盘.board%$    // 回调输出文本即为返回结果
%胜者%                                // 拿到结果

[内部]检查胜负 (.+)
棋盘:%括号1%
...计算...
%胜者%                                // 输出胜者数字（0/1/2）
```

> **回调内的赋值不会回传调用方**（与 `[函数]` 的 `->变量` 传出机制不同）。
>
> ✗ 错误样板（以为回调里赋的值调用方也看得见）：
> ```
> 五子棋
> 棋盘:$回调 初始化棋盘$   // 期望回调内给 %棋盘% 赋了值、返回后还能用
> 棋盘文本:$回调 显示棋盘$ // ✗ 实际读到的是空：回调内赋值只在回调内生效
> ```
> 为什么错：回调内对变量的赋值发生在回调自己的局部环境，**不会写回调用方**；调用方能拿到的只有回调的**输出文本**。
> ✓ 正确样板（回调输出结果，调用方用 `变量:$回调 ...$` 捕获）：
> ```
> 五子棋
> 棋盘:$回调 初始化棋盘$   // 回调最后一行输出完整状态 JSON，这里捕获
> 棋盘文本:$回调 显示棋盘$
> ```
> 回调内改了状态要同步回调用方时，在调用方显式重新赋值（如 `棋盘:%新棋盘%`），不要把状态更新全放在回调内部。

### 函数定义

> `[函数]` 定义内容里可用 `$函数名$` 调用其他函数（其他 `[函数]`、函数框或内置函数），实现函数复用与嵌套调用。
> 函数名不可与系统内置函数重名：重名时编译报警告，且调用该函数名会直接报错「禁止覆盖系统内置函数」（内置函数为只读）。

支持缩写[F]（即 [函数]）
```
Main
$ok$
$hi 世界$

[函数]ok
b

[函数|1]hi
你好，%参数1%
```

> **函数体内多行文本同样直接拼接不换行**（与正文换行规则一致，见「一、认识词库 → 换行规则」）：函数返回的多行内容要用行尾 `\r`、`%换行%` 或 `文本>` 块显式拼出换行，否则多行会粘成一行。
> ```
> [函数]显示棋盘
> 第一行\r
> 第二行\r
> 第三行      // 无 \r 结尾
> ```
> 调用 `$显示棋盘$` 返回 `第一行\n第二行\n第三行`。

##### 参数数量

> 函数统一按**函数名精确匹配**（不再使用正则），并校验参数个数；参数规则用 `[函数|规则]名称` 声明，未声明 `|规则` 时默认 0 个参数（等价于 `[函数|0]名称`）。
> 规则与内置函数一致：`1`（恰好 1 个）、`1|2`（1 到 2 个）、`1..`（1 到无限个）、`..3`（最多 3 个）等，可组合如 `1|3|5..`。
> 类函数同样支持，写作 `[函数:类名|规则]名称`。
> 函数名为纯标识符，不支持空格或特殊符号（如 `.`、`%`、`|`、`->` 等），否则会与参数分隔、对象方法、变量传出等语法冲突。
> 参数数量不符时与内置函数一致：输出 `参数数量错误` 并停止执行，不会静默返回原文。

```
Main
$计算 5$
$计算 5 6$
$打招呼 世界$

[函数|1|2]计算
%参数1%

[函数|1..]打招呼
你好，%参数1%
```

> 未声明 `|规则` 时默认 0 个参数：`[函数]名称` 等价于 `[函数|0]名称`，调用时带参数会报 `参数数量错误`。
>
> **典型错误（实测）**：函数要用 `%参数N%` 接收调用方传入的值，就必须声明参数规则，否则调用方传参直接报错：
> ```
> 单价:$获取单价 %鱼名%$      // 调用传了 1 个参数
> 
> [函数]获取单价->单价         // 错误：未声明 |规则，默认 0 参，报「参数数量错误(需要0，实际1)」
> 如果>%参数1%==鲫鱼
>     ...
> <如果
> ```
> 正确写法是 `[函数|1]获取单价->单价`。**凡函数体内出现 `%参数N%`，定义处都必须声明 `[函数|N..]`**。

##### 捕获报错

> 函数名以 `!` 开头调用（`$!函数名 参数$`）时，会捕获该函数的报错：报错时把错误文本写入「报错」变量（用 `%报错%` 读取），函数不返回错误文本，**不会**停止后续执行；无报错时「报错」变量为空。
> 适用于希望函数失败后继续执行、由脚本自行判断处理结果的场景。

```
Main
$!计算 5 6$
%报错%

[函数|1]计算
%参数1%
```

> 上述调用因参数数量不符，`%报错%` 输出错误信息，但 Main 后续内容仍会继续执行。

##### 变量作用域

> **函数体内的赋值默认只在函数内生效（函数局部），不会写回外部**（实测）：
> - 函数内 `a:1` 赋值后，调用结束外部 `%a%` **读不到值**（原样输出为空），同时外部已有的同名变量**不会被覆盖**——函数内与外部是两套独立变量；
> - 要让函数内计算的结果带回外部，必须在定义处声明传出列表 `[函数]名称->变量1,变量2`，函数内对这些变量的赋值会在调用结束后写回外部（见下「变量传出」）；
> - `$全局变量 键 值$` 可主动读写全局变量（不受函数局部限制）。

```
✗ 错误：函数内赋值，外部读不到

$测试$
a=%a%       // 输出 a=（空，函数内 a 没有传出）

[函数]测试
a:1

✓ 正确：声明传出列表，外部才能读到
Main
$测试$
a=%a%       // 输出 a=1

[函数]测试->a
a:1
```

### 计算

> 支持运算符号
```
加 +
减 -
乘 *

```

```
[2*(1+1)]
```

> **`[...]` 是算术表达式**：支持括号与正常优先级（`[2*(1+1)]` = 4），**可以直接写进函数参数**里（值处替换 `$计算`）：
> ```
> $延迟 [1000*%秒%]$              // 参数位置直接算
> $写 a.txt 值 [%旧值%+1]$
> $函数名 [%x%*2+%y%]$
> ```
> 与 `$计算` 的区别：`$计算` 是函数（严格左到右、无括号、支持空格分隔的中文运算符），`[...]` 是嵌入在任意函数参数里的表达式（标准运算顺序）。注意 `[...]` 内不能再嵌套 `$函数$`（见「注意事项」），需要函数结果时先 `变量:$函数$` 存好再用 `%变量%` 参与运算。

```
$计算 1 加 1$
$计算 1 + 1$
$计算 1 减 1$
$计算 1 - 1$
$计算 1 乘 1$
$计算 1 * 1$
$计算 1 除 1$
$计算 1 / 1$
$计算 1 除余 1$
$计算 1 % 1$
$计算 1 按位或 1$
$计算 1 | 1$
$计算 1 << 1$
$计算 1 左移 1$
$计算 1 >> 1$
$计算 1 右移 1$
$计算 1 根号 1$// 平方根
$计算 1 sqrt 1$
$计算 1 四舍五入 1$
// 支持链式计算
$计算 1 + 2 + 3$
$计算 1 + 2 * 3$
$计算 10 除 2 加 3 乘 4$
```

> **`$计算` 严格从左到右求值，没有运算符优先级，也不支持括号**（实测）。
>
> ✗ 错误样板（先加后乘，结果整体偏移）：
> ```
> $计算 1 + 2 * 3$      // 期望 7，实际 (1+2)*3 = 9
> $计算 4 - 1 * 2$      // 期望 2，实际 (4-1)*2 = 6
> $计算 1 + (2 * 3)$    // 期望 7，实际 Error（括号不支持）
> 行2:$计算 %行% + %dx% * %步%$   // AI 落子坐标推算错位
> 总评分:$计算 %评分% + %防守评分% * 0.9$   // AI 评分整体偏移
> ```
>
> 为什么错：`$计算` 按从左到右顺序**两两计算**，加减乘除没有优先级；括号会被当非法输入返回 `Error`。五子棋 AI 落子评分、坐标推算都因此算错位置、选错落点。
>
> ✓ 正确样板（乘法写最前、加法收尾；减号项用 `0 -` 前置改写成加法）：
> ```
> 行2:$计算 %dx% * %步% + %行%$       // 行 + dx*步
> 行2:$计算 0 - %dx% * %步% + %行%$   // 行 - dx*步
> 总评分:$计算 %防守评分% * 0.9 + %评分%$   // 评分 + 防守*0.9
> ```
> 需要标准运算顺序（含括号、优先级）时改用 `[...]` 算术表达式（见上方），不要用 `$计算`。

##### 储存习惯与路径组织

`$读/写 路径 键 数据$` 的路径都从 `database/` 目录下开始，规划路径时按以下习惯组织（便于检索与迁移）：

- **路径分层用 `/` 分隔**，按「游戏/功能 → 分类 → 用户」组织：`$写 钓鱼/普通/123456.txt 背包 %背包%$`、`$写 钓鱼/限时/789.txt 进度 ok$`。
- **推荐「不用群号、专注 QQ」记录用户数据**：路径写 `<游戏名>/<分类>/<QQ>.txt` 即可。这样同一个用户在不同群、不同功能下用的是同一份数据；若把群号编进路径（`<群>/<QQ>.txt`），同一用户在 A 群和 B 群的数据互相隔离，后续跨群统计、账号合并会很麻烦。**只有数据确实需要按群隔离时才用 `<群号>` 层**。
- **文件名不要太长**：直接用 `<QQ>.txt`、`背包.json` 这类简短名字即可，不要拼一大串描述（如 `123456_钓鱼_第3赛季_当前背包数据.txt`），长文件名在迁移、调试、日志里都难处理；需要描述信息就放进键名或文件内容里。
- **多拆分文件夹分类，一个文件夹下尽量全是文件、不要再有文件夹**：`钓鱼/普通/`、`钓鱼/限时/`、`签到/`、`礼包/` 这类「一层功能、一层分类」即可；避免一个目录下文件夹套文件夹套好几层（如 `data/a/b/c/d.txt`），目录过深既不直观也容易撞路径。需要扩展时就新开一个顶层分类文件夹。
- 文件后缀用 `.txt`（文本数据）或 `.json`（结构数据，键支持 `.` 多层读写），见上「写入数据」。

### 数据处理

#### JSON 操作

```
$JSON解析 <json> <键>$
// 存可以改成存字只存文本数据
// 可以直接通过多层键设置值
$JSON存 <json> <键>... <值>$
// $JSON存 {} a b 内容$ 返回 {"a"{"b":"内容"}}
$JSON存字 <json> <键>... <值>$
// 这是给元素追加用的
$JSON追加 <json> <值>$
$JSON追加字 <json> <值>$
$JSON存在 <json> <键>$
$JSON删 <json> <键>$
```

> `$JSON解析` **一次只取一层**（`<json> <键>` 两个参数，键可以是 `->` 路径批量解析）。取嵌套值要分步或换 `%@变量.键.索引%`：`$JSON解析 %棋盘% 行索引$` 拿到行数组，再 `$JSON解析 %行% 列索引$`；写成三个参数（如 `$JSON解析 %棋盘% 2 3$`）会报 `参数数量错误`。
>
> **`$JSON删` / `$JSON存` 等「返回新 JSON」的函数必须把返回值赋给变量**，原变量**不会**被就地修改（实测）：
> ```
> $JSON删 %背包% 草鱼$            // 错误：返回值被丢弃，删除没生效，%背包% 还是原样
> 背包:$JSON删 %背包% 草鱼$       // 正确：新 JSON 赋回变量
> ```
> 写成 `背包:$JSON删 %背包% 草鱼$` 后 `%背包%` 才是删掉草鱼的新 JSON。
>
> **`$JSON存` 写嵌套值时键路径必须写全，漏写中间键会把整层替换成新值**。
>
> ✗ 错误样板（只给一层键，漏了行索引）：
> ```
> 新棋盘:$JSON存 %棋盘% board %行数组%$   // 期望改 board[行] = 行数组
> ```
> 为什么错：`$JSON存` 的 `<键>...` 是多层键路径，漏写中间键时**不是追加而是整体替换**——15×15 棋盘的 `board` 被换成一行扁平数组，其余 14 行全部丢失，导致误判胜利、存盘数据损坏。
>
> ✓ 正确样板（先取子层、改子层、带完整键路径写回父层）：
> ```
> 行数组:$JSON解析 %棋盘% board %行%$      // 1. 取出要改的子层
> 行数组:$JSON存 %行数组% %列% 1$          // 2. 修改子层元素
> 棋盘:$JSON存 %棋盘% board %行% %行数组%$  // 3. 完整键路径 board + 行 写回
> ```
>
> **`$函数$` 必须成对闭合，漏写闭合 `$` 会让整条函数调用失效**：
>
> ✗ 错误样板（末尾漏了闭合 `$`）：
> ```
> 棋盘:$JSON存 %棋盘% board %行数组%$
> 棋盘:$JSON存 %棋盘% board %行数组%   // ✗ 少一个 $，赋值落空
> ```
> 为什么错：`$函数$` 缺闭合 `$` 时该函数调用不被执行，赋值变量损坏/为空、后续引用全部失效，常表现为「功能静默不生效、输出为空」（五子棋开局棋盘变量损坏、输出为空的根因）。
> ✓ 正确写法：每个 `$函数$` 成对闭合，写完检查行内 `$` 数量为偶数。

##### JSON美化

第二个参数是**缩进字符串**，原样作为每层缩进前缀，**不是空格数量**：传 `1` 得到字面 `1` 缩进、传 `"  "`（带引号的两个空格）才得到空格缩进（实测 `$JSON美化 {"a":1} 1$` → `{\n1"a": 1\n}`）。默认（可留空）是两空格。

##### JSON重名解析

支持重名 key 解析、数组按索引或键值对匹配查询。
```
// 普通对象解析（等同于 JSON解析）
$JSON重名解析 {"a":{"b":1}} a->b$
// → 1

// 重名 key 自动合并为数组
$JSON重名解析 {"a":"b","a":"c"} a$
// → ["b","c"]
$JSON重名解析 {"a":"b","a":"c"} a->0$
// → "b"

// 数组按索引访问（数字开头）
$JSON重名解析 [{"name":"Alice","age":20},{"name":"Bob","age":30}] 0->age$
// → 20
$JSON重名解析 [{"name":"Alice","age":20},{"name":"Bob","age":30}] 1->name$
// → Bob

// 数组按键值对匹配（非数字开头）
$JSON重名解析 [{"name":"Alice","age":20},{"name":"Bob","age":30}] name->Bob->age$
// → 30
```

##### JSON赋予值

> **块内内容是原样 JSON**：键必须带引号（`"键":值`），值里的 `%变量%` 要写在**引号内**（`"键":"%变量%"`），整段值只有 `%变量%` 时会按类型填入（数字仍是数字）；**裸写 `%变量%`（不带引号）会让整块解析失败返回 error**。行内缩进、逗号后的空格都没问题。**块内 `$函数$` 不会执行**，残留的 `$...$` 是非法 JSON 字符，同样会让整块返回 error——需要函数结果请先 `变量:$函数$` 存起来再在块内 `%变量%` 引用。

```
a:123
a:{
    "a":"a",
    "b": "%a",
    "c": "s%a"
}
```

```
a:123
a:[
    "a",
    "%a",
    "s%a"
]
```

##### JSON框（`JSON>` 键=值形式）

与上面 `变量:{`/`变量:[`（原样 JSON）不同，`JSON>` 框按**键=值**设置项逐行构建对象/数组，键支持 `->` 多层路径（见「三、语言基础 → JSON框」）：

```
JSON>赋予值={}
a=b
a->a=b
<JSON
```

```
JSON>[]
0=a
1=b
<JSON
```

> 关键规则（实测）：
> - 开启行写死 `JSON>变量={}` / `JSON>[]`，**后面不要再单独写 `}` / `]` 行**，直接跟键=值行，以 `<JSON` 闭合；
> - 键=值行**行尾不能带逗号**——尾逗号会让整块静默失效、无任何输出；
> - `键=值`：值按**文本**存入（`棋盘=%棋盘%` 会存成字符串 `"[[0,1],[1,0]]"`）；
> - `键:=值`：值**保留类型**（数字仍为数字、JSON 数组/对象原样嵌入），需要嵌入数组/数字时用 `:=`：`棋盘:=%棋盘%` → `{"棋盘":[[0,1],[1,0]]}`；
> - 块的结果直接作为该行的输出，也可在块后 `%变量%` 读取。

#### 创建服务器

创建一个独立的 HTTP 词库服务器。每个请求以 **URL 路径作为触发词**运行词库，输出作为 HTTP 响应。返回「服务器对象」（面对像）。

> 创建后**不会立即启动**，需调用 `$甲.启动$` 后才开始监听端口。
> **第二参数接受编译好的词库数据**（gob 字节编译产物，或直接把 `$编译词库$` 返回的 map 传入自动取「编译数据」），不是源码文本、也不是文件路径；可留空，留空后先用「设置路由词库」补齐再启动。
> 编译产物可由 `//@资源 变量:xxx.n` 自动编译得到，或用 `$编译词库$` 编译后取「编译数据」。
> 可在启动词库 `start.n` 中调用本函数，实现程序启动时自动创建独立服务器。
> **核心服务器**：多台函数服务器中会标记一台为核心，用于承载管理面板（OPUI）、防火墙、云工具、机器人 webhook、WebSocket 服务等内置入口，其余服务器仅跑词库路由。核心身份**不会自动指定**（第一个创建的服务器也不默认核心），须启动后调用 `$甲.设置核心服务器$` 显式标记，标记后其余服务器自动取消核心。核心服务器的 WebUI 地址可用 `$核心服务器$` 获取。
> **BeerFrp 穿透**：可用 `$甲.设置BeerFrp 开关 调试 令牌 服务器地址$` 配置（默认 true / false / 空 / wss://frp.cjxpj.com），或在前端「服务器列表」编辑弹窗中配置，保存后立即建立/断开隧道。

**创建服务器**

```
// 端口地址可写 8080 或 :8080；词库数据可留空，留空后先用「设置路由词库」补齐再启动
甲:$创建服务器 <端口地址> <编译好的词库数据>$

// 先编译源码（返回 JSON），再把整个 JSON 传给创建服务器（自动取「编译数据」字段）
编译:$编译词库 a$
甲:$创建服务器 8999 %编译%$
```

**服务器对象方法**

```
// 启动服务器，开始监听端口（端口被占用会报错）
$甲.启动$

// 设置路由词库：支持编译好的词库数据（$编译词库$ 返回值或 //@资源 编译产物）或词库文件路径/源码，内部立即生效
$甲.设置路由词库 <编译好的词库数据 | 词库路径 | 源码>$

// 停止服务器释放端口
$甲.关闭$

// 设置对象变量（变量随服务器一直存在）
$甲.设置变量 键 值$

// 设置是否允许跨域（创建时默认 true）
$甲.设置跨域 false$

// 将当前服务器标记为核心服务器（须先启动），其余自动取消核心；
// 核心承载管理面板（OPUI）/防火墙/云工具/机器人 webhook 等内置入口，不标记则仅跑词库路由
$甲.设置核心服务器$

// 配置 BeerFrp 穿透：开关 / 调试 / 令牌 / 服务器地址（默认 true / false / 空 / wss://frp.cjxpj.com）
$甲.设置BeerFrp true false 令牌 wss://frp.cjxpj.com$
```

**读取对象变量**

```

#### 编译词库

把词库源码编译，直接返回 **map 结构数据**（不经 JSON 序列化与 base64 编解码，避免数据错误），含三个键：**编译数据**（原始 gob 字节 `[]byte`）、**报错数据**、**警告数据**（报错/警告为数组，元素含 `line` / `text` / `level`）。

```
编译:$编译词库 <词库数据>$
```

> 「编译数据」可直接传给 `$创建服务器$` 作为第二参数（直接传整个 map，创建服务器自动取「编译数据」字段）。
> 词库含自定义函数（bot 注入）时无法序列化，「编译数据」为空（对应报错）。
> 等价于 `//@资源 变量:xxx.n` 对 `.n` 词库的自动编译结果。

#### 核心服务器

返回当前核心服务器的 WebUI 地址（`http://localhost:端口/管理面板路径`）；已生成快捷登录码时自动拼接 `?key=快捷登录码`，供启动词库打印后直接快捷登录；无核心服务器时返回空串。

```
$核心服务器$
```

> 核心服务器由 `$创建服务器$` 体系维护：创建后**不会自动成为核心**，须调用 `$服务器.设置核心服务器$` 显式指定。
> 示例（启动词库打印）：`WebUi: $核心服务器$`。

        <h1>文本</h1>
        <h1>文本2</h1>
        <p>文本2</p>
    </body>
</html>
"""

// 不指定路径 → 返回完整 JSON 树
$HTML解析 %a%$

// 叶子节点 → 文本数组
$HTML解析 %a% html head title$    // ["标题"]
$HTML解析 %a% html body h1$       // ["文本","文本2"]
$HTML解析 %a% html body p$        // ["文本2"]

// 容器节点 → JSON 节点数组
$HTML解析 %a% html body$          // [{h1节点},{h1节点},{p节点}]

// 索引选取单个 → 叶子返回文本，容器返回 JSON 对象
$HTML解析 %a% html body h1 0$     // "文本"
$HTML解析 %a% html body h1 1$     // "文本2"
$HTML解析 %a% html body 0$        // {h1节点JSON}
```

#### 正则

> 正则写法以 Go 语言为准。Java 里常用的「环视/预查」`(?=...)`、`(?<=...)`、「反向引用」`\1`，以及 `\uXXXX`（Unicode 字符）在 Go 里都不支持，Unicode 字符要改用 `\x{XXXX}` 写；普通匹配照常写即可，比如 `\d+` 匹配数字、`^abc` 匹配开头、`[abc]` 匹配 a/b/c 之一。

### 全局数据库 money 表（经济系统）

> 内置 `money` 表，以 `类型 + 账号` 作为联合主键（索引），余额为整数，未存在的账号余额视为 0。

- **数值类型**：仅支持整数，**不支持小数**（传入小数会被解析为 0）。
- **存储上限**：余额为 SQLite `INTEGER`（Go `int64`），范围 `-9223372036854775808 ~ 9223372036854775807`（约 ±922 京），超出会溢出。
- **负数**：`db_设置` 支持设为负数；`db_减少` 可减到负数。

```

// 减少余额，返回操作后的余额
$db_减少 <类型> <账号> <整数>$

// 直接设置余额（可为负数），返回操作后的余额
$db_设置 <类型> <账号> <整数或负数>$

// 查询余额：账号留空返回 {} 数据（账号->余额），否则返回 {"余额":...,"排名":...}
$db_查询 <类型>$
$db_查询 <类型> <账号>$

// 查询排名：按余额降序返回；页数留空返回全部列表，页数默认 1，显示数量默认 10

**消息变量**（Bot 消息回调时自动注入）

| ---- | ---- |

| `%昵称%` | 发言者昵称 |
| `%管理%` | 群内角色：`1`=群主(owner), `2`=管理员(admin), `0`=普通成员 |

| `%robot%` / `%Robot%` | 机器人 union_openid（需特殊申请，取不到时回退到配置的 Robot 变量值） |

**群事件变量**（入群/退群/入群申请事件回调时自动注入，非普通消息）

| 变量 | 说明 |
| ---- | ---- |
| `%来源%` | 来源描述：`群成员加入` / `群成员退出` / `机器人进群` / `机器人退群` / 入群申请 / 按钮 / 快捷菜单 / `好友添加` / `好友删除` / `机器人上线` |

| `%功能ID%` | 快捷菜单功能 ID（仅快捷菜单回调事件有值，管理端设置） |

| `%成员%` | 加入/退出事件的成员 OpenID（入群申请/好友事件无） |

| `%QQ%` / `%qq%` | 成员/好友 QQ OpenID（成员事件取 `member_openid`；机器人事件取操作者 `op_member_openid`；好友事件为好友 OpenID） |
| `%头像%` | 成员/好友头像 `http://q.qlogo.cn/qqapp/{AppID}/{QQ}/640` |
| `%昵称%` | 入群申请人的昵称（仅入群申请事件） |
| `%申请理由%` | 入群申请验证消息内容（仅验证消息模式有值，仅入群申请事件） |
| `%申请问题%` | 入群申请问答内容，格式 `问题:答案` 以 `;` 分隔（仅问答模式有值，仅入群申请事件） |
| `%申请时间%` | 入群申请时间（仅入群申请事件） |
| `%申请来源%` | 入群申请来源（仅入群申请事件） |
| `%申请ID%` | 入群申请 ID（用于 `入群审批` 主动审批，仅入群申请事件） |
| `%robot%` / `%Robot%` | 机器人 union_openid（需特殊申请，取不到时回退到配置的 Robot 变量值） |
| `%robot_appid%` | 机器人 AppID |

> 进群事件触发词为 `[群事件]群成员进群`，退群事件触发词为 `[群事件]群成员退群`，机器人进群触发词为 `[群事件]机器人进群`，机器人退群触发词为 `[群事件]机器人退群`，入群申请事件触发词为 `[群事件]入群申请`，好友添加触发词为 `[内部]好友添加`，好友删除触发词为 `[内部]好友删除`，按钮回调事件触发词为 `[按钮事件]<data>`，快捷菜单回调事件触发词为 `[菜单事件]<功能ID>`，机器人上线触发词为 `[系统]启动`，可直接在词库中监听。
> 机器人进群的回复在群内发送（官方支持 event_id 被动回复）；机器人退群的回复以私信形式发送给踢出机器人的人。
> 群成员进群走 event_id 被动回复（回复在群内发送）；群成员退群、入群申请为主动推送事件，回复走主动消息，需群主开启【机器人主动在群聊内发言】后才能成功发送到群内。
> 好友添加/删除事件的回复以私信形式发送给该好友用户。
> 快捷菜单（自定义菜单）仅单聊场景，回调回复以私信形式发送给点击用户，触发词为管理端配置的功能 ID。

$发送视频 <视频数据>$
$发送语音 <语音数据>$
$流式发送 <内容> <状态(可选)> <stream_msg_id(可选)> <index(可选)> <内容类型(可选)>$
$禁 <群OpenID> <成员OpenID> <禁言秒数>$     // 不传群号则取当前群；0 表示解禁
$踢 <群OpenID> <成员OpenID>$                // 移除群成员（踢出群）
$踢黑 <群OpenID> <成员OpenID>$              // 移除群成员并加入群黑名单
$获取群信息 <群OpenID>$                   // 参数留空则取当前群号，返回群信息 JSON
$获取机器人群内状态 <群OpenID>$            // 参数留空则取当前群号，返回机器人群内状态 JSON
$入群审批 <群OpenID> <成员OpenID> <op> <申请ID(可选)> <拒绝理由(可选)>$   // op: 同意 / 拒绝 / 拉黑拒绝，群号必填
$撤回 <消息ID>$                              // 撤回当前群消息（机器人消息 2 分钟内）

$撤回私聊 <消息ID>$                          // 撤回当前单聊消息
$撤回私聊 <用户OpenID> <消息ID>$             // 撤回指定单聊消息
```

> 回复函数使用当前消息上下文（群OpenID、MsgID），仅在 QQBot 消息回调触发的词库中可用。

> **词库正文直接输出的文本就会自动作为回复发送，一般无需调用这些函数**：触发词下面的文本行、`文本>` 块、`%变量%` 拼接等内容，执行完由框架统一回复给发消息的人。上面的回复函数只在需要**主动补发一条额外消息**（如回复一条后接着再发一条）、或需要带图/带按钮（`发送文本` 的第二参数图片数据、`发送MD` 按钮）时使用。

> `发送MD` 群聊/私聊用法一致：单参数为 MD 文本直接发送；多参数为 `模板ID 键1 值1...`，键值必须成对，不成对会报错"要设置对应键跟值"。

> `流式发送` 仅单聊（C2C）可用，用于流式分批发送 Markdown/文本消息：`状态` 为 `1`（生成中）或 `10`（生成结束，默认）；`stream_msg_id` 首片留空、续片传入上一片返回的 id；`index` 从 0 递增（默认 0）；`内容类型` 为 `text` / `markdown`（默认 markdown）。函数返回首片生成的 stream_msg_id。

**入群申请处理**

通过 `入群审批` 同意或拒绝入群申请：

```
// 同意入群（ReplyFuncs，%群号% 群OpenID，%QQ% 为申请人 OpenID，%申请ID% 为审批令牌）
$入群审批 %群号% %QQ% 同意 %申请ID%$

// 拒绝入群并附带拒绝理由（ReplyFuncs）
$入群审批 %群号% %QQ% 拒绝 %申请ID% 不符合入群条件$

// 拒绝入群并同时加入群黑名单（ReplyFuncs，op 传 拉黑拒绝）
$入群审批 %群号% %QQ% 拉黑拒绝 %申请ID% 不符合入群条件$

// 主动审批（ActiveFuncs，需 #引入=@QQBot）

// 主动拒绝并附带拒绝理由（ActiveFuncs）

**消息按钮（Keyboard）**

`发送MD` 通过 `按钮` 关键字分隔按钮定义，按钮使用参数串格式传递。第二参数为 JSON（`{"rows":[...]}` 或 `{"id":"..."}`）时自动解析为键盘。自定义按钮仅支持简单文本模式（`$发送MD <Markdown内容> 按钮 ...$`）；模板模式（`$发送MD <模板ID> <键1> <值1>...`）不支持自定义按钮，仅插入文本，键/值可正常使用"按钮"字样：

```
// [样式数字]标签[|数据]（\r 后缀换行；样式 [0]~[3]，默认 [0]）
$发送MD "# 标题\n内容" 按钮 [1]确认|/确认 [0]取消|/取消\r$

// 简写：标签|数据，自动推断类型
$发送MD "# 菜单" 按钮 查看详情|https://example.com 确认|#回调操作$
// → "查看详情" 外显为链接网址，"确认" 外显为回调按钮 data=回调操作

// data 以 # 开头自动为回调（type=1），触发词格式：[按钮事件]data
$发送MD "# 请确认" 按钮 确认|#确认操作 取消|#取消操作$

// 二次确认弹窗：#[取消文案|确认文案]提示，点击回调按钮先弹窗，[] 后的文本同时作为按钮文字、回调 data 和弹窗提示
$发送MD "# 危险操作" 按钮 #[取消|确认]确定执行？\r$

// 对应的回调触发词定义
[按钮事件]确认操作
%QQ% 已确认

[按钮事件]取消操作
%QQ% 已取消

// 模板模式不支持自定义按钮，仅插入文本，"按钮"可正常作为键/值
$发送MD 模板ID key val 按钮 了解更多$
```

按钮 type（由 data 前缀自动推断）：`0`=跳转链接（data 以 http 开头），`1`=回调（data 以 `#` 开头），`2`=指令（默认，输入框自动填充 data）
按钮样式（开头 `[数字]`）：`0`=灰色线框（默认），`1`=蓝色线框
按钮 permission.type：`0`=指定用户，`1`=仅管理者，`2`=所有人

**JSON 键盘**（`发送MD` 第2参数 与 `群单发MD` 第4参数均支持）：
```
$发送MD "# 标题" {"rows":[{"buttons":[{"id":"1","render_data":{"label":"确认","visited_label":"已确认","style":1},"action":{"type":2,"permission":{"type":2},"data":"/确认","enter":true}}]}]}$
$群单发MD 1 群OpenID "# 标题" {"rows":[{"buttons":[{"id":"1","render_data":{"label":"确认","visited_label":"已确认","style":1},"action":{"type":2,"permission":{"type":2},"data":"/确认","enter":true}}]}]}$
$群单发MD 1 群OpenID "# 标题" {"id":"123456"}$
```

**按钮回调事件**

action.type=1（回调按钮）点击后触发 `INTERACTION_CREATE` 事件，框架自动回应并转为词库消息处理。触发词格式为 `[按钮事件]<data>`（`/` 前缀会被剥离），支持 `%QQ%（点击者）` / `%群号%` / `%来源%（=按钮）` 等事件变量。

可通过 `$设置状态 <状态码>$` 控制按钮交互的返回结果：
- `0`：成功（默认）
- `1`：操作失败
- `2`：操作频繁
- `3`：重复操作
- `4`：没有权限
- `5`：仅管理员操作

```
// 发送带回调按钮的 MD（标签|#数据），data 中 / 前缀会被剥离
$发送MD "# 请确认操作" 按钮 确认|#确认操作 取消|#取消操作$

// 对应的回调触发词定义
[按钮事件]确认操作
已收到 %QQ% 的确认！

[按钮事件]取消操作
%QQ% 取消了操作
```

**词库示例**：
```
// 发送带回调按钮的 MD
$发送MD "# 菜单\n点击按钮确认" 按钮 确认|#确认操作 取消|/取消$

// 监听按钮回调

## 十、扩展开发（动态库）

> 扩展是一段用 C 编写、编译成 `.dll`（Windows）或 `.so`（Linux/Android/鸿蒙）的原生动态库。主程序在**运行时**加载它，通过固定的 C ABI 枚举并调用其中注册的字典函数，使词库可用 `$函数名$` 调用扩展能力。适合需要原生性能、调用第三方 C/C++ 库，或希望**不重新编译主程序**即可扩展函数的场景。

### 标准接口

扩展动态库需导出以下固定符号（C 链接，C++ 下用 `extern "C"` 包裹）：

| 符号 | 签名 | 说明 |
| --- | --- | --- |
| `ext_init` | `int ext_init(void)` | 初始化，返回 `0` 成功、非 `0` 失败 |
| `ext_close` | `void ext_close(void)` | 退出清理 |
| `ext_count` | `int ext_count(void)` | 注册的函数数量 |
| `ext_name` | `const char* ext_name(int index)` | 第 `index` 个函数名（UTF-8） |
| `ext_l` | `const char* ext_l(int index)` | 第 `index` 个函数的参数规则 `L`（如 `"0"`、`"1|2"`、`"2.."`） |
| `ext_call` | `const char* ext_call(const char* name, const char* const* args, int argc, const char** err)` | 调用函数；成功返回结果字符串（可为 `NULL` 表示空串）并把 `*err` 置为 `NULL`，失败返回 `NULL` 并把 `*err` 指向错误信息 |

> 返回字符串（`ext_name` / `ext_l` / `ext_call` 的结果与错误信息）指向的缓冲区需在下一次调用本扩展或 `ext_close` 之前保持有效；服务端会立即复制，因此使用单个静态缓冲区即可。服务端串行调用扩展，无需考虑多线程并发。

### 示例

```c
#include "ext.h"

static const struct { const char* name; const char* l; } funcs[] = {
    {"扩展测试", "0"},
    {"扩展回显", "1"},
    {"扩展加法", "2"},
    {"扩展报错", "0"},
};

static char buf[4096];

int ext_init(void) { return 0; }
void ext_close(void) {}
int ext_count(void) { return (int)(sizeof(funcs) / sizeof(funcs[0])); }
const char* ext_name(int i) { return (i >= 0 && i < ext_count()) ? funcs[i].name : NULL; }
const char* ext_l(int i) { return (i >= 0 && i < ext_count()) ? funcs[i].l : NULL; }

const char* ext_call(const char* name, const char* const* args, int argc, const char** err) {
    *err = NULL;
    if (strcmp(name, "扩展测试") == 0) { snprintf(buf, sizeof(buf), "扩展加载成功"); return buf; }
    if (strcmp(name, "扩展回显") == 0) { snprintf(buf, sizeof(buf), "%s", argc > 0 && args[0] ? args[0] : ""); return buf; }
    if (strcmp(name, "扩展加法") == 0) {
        double a = argc > 0 && args[0] ? atof(args[0]) : 0;
        double b = argc > 1 && args[1] ? atof(args[1]) : 0;
        snprintf(buf, sizeof(buf), "%g", a + b); return buf;
    }
    if (strcmp(name, "扩展报错") == 0) { *err = "这是一个测试错误"; return NULL; }
    *err = "未知函数";
    return NULL;
}
```

### 编译

在扩展工程目录编译（Windows 需 MinGW-w64 等 GCC 工具链）。以下参数会做体积优化：`-Os` 优化体积、`-s` 去除符号、`--gc-sections` 剔除未使用代码，产物通常只有几 KB：

```
Windows：gcc -shared -Os -s -ffunction-sections -fdata-sections -Wl,--gc-sections -fno-asynchronous-unwind-tables -fno-stack-protector -o 我的扩展.dll main.c
Linux/Android/鸿蒙：gcc -shared -fPIC -Os -s -ffunction-sections -fdata-sections -Wl,--gc-sections -fno-asynchronous-unwind-tables -fno-stack-protector -o 我的扩展.so main.c
```

将编译产物放入主程序数据目录 `private/plugins/` 下，重启主程序即可加载。扩展仅在启动时加载一次，运行期不热更新；修改扩展后需重新编译并重启主程序生效。

### 加载目录

主程序启动时自动扫描 `private/plugins/` 目录，加载其中的 `.dll`（Windows）或 `.so`（其他平台）扩展：

- 每个扩展通过导出符号 `ext_init` 初始化，`ext_count` / `ext_name` / `ext_l` 声明函数列表，主程序据此注册字典函数。
- `ext_close` 对应退出清理。

### 函数参数与返回值

- 参数：词库传入的参数由服务端转换为字符串（`string` → 原文、数字 → 十进制、布尔 → `true`/`false`）后，以 `const char* const* args` + `argc` 传给扩展。
- 返回值：扩展返回字符串（`const char*`）作为词库函数结果，返回 `NULL` 表示空字符串。
- 参数数量规则 `L` 与内置函数一致：`"0"` 无参、`"1|2"` 一或两个参数、`"2.."` 两个及以上参数。

完整可编译的 C 示例见 `nebula/examples/ext/`（含 `ext.h` 接口头文件、`main.c` 示例与 `build.ps1` 编译脚本）。

### 注意事项

- **函数名不可与内置函数或其他扩展冲突**：冲突时会在日志报错并跳过，不会覆盖内置函数。
- **接口为原生 C ABI、字符串传参**：参数与返回值均为字符串，无法直接传递复杂对象；需要结构化数据时可在扩展侧自行解析/构造 JSON 或自定义格式。
- **需 GCC 工具链编译**：Windows 需安装 MinGW-w64 等 GCC 工具链。
- 扩展函数会自动出现在管理面板的词库补全列表中（`ListFuncs()` 实时返回），无需手动同步前端。
- 主程序加载扩展在 Windows 用纯 Go 的 `LoadLibrary`（无需 CGO）；Linux/Android/鸿蒙需主程序以 CGO 构建（`dlopen`）。若主程序在无 CGO 的 Linux 环境构建，扩展加载能力不可用（仅跳过，不报错）。
