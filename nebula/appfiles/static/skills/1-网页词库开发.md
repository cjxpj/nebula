【网页词库开发（WebNebula / .wn）】
目标：编写 / 修改 .wn 网页词库，让网页被访问时由脚本生成内容。写脚本块前先读取「词库语法结构」技能——.wn 的脚本块与 .n 共用同一套 Nebula 语法。

一、文件与位置
1. .wn 是「HTML 容器 + 内嵌脚本块」的网页词库，UTF-8 编码，默认放在网站根目录（public/）下，访问路径即文件路径：public/index.wn ↔ /index.wn（默认首页），public/404.wn ↔ /404.wn（页面不存在时的兜底页）；
2. 请求由 system/router.n 路由：.wn 分支先 $设置头部 Content-Type text/html;charset=UTF-8$ 再 $执行网页词库文件 <路径>$；文件不存在时输出 404.wn。

二、执行模型（与机器人 .n 完全不同，最容易搞错）
1. .wn 没有触发词：文件里的脚本块自上而下依次执行，不等待任何消息——不要写 Main，也不要用 %参数N%（那是消息匹配用的）；本智能体产出的文件一律是 .wn，禁止写成 .n，也禁止出现「触发词独占一行 + 正文」这种 .n 词条结构；
2. 只识别直接挂在 <head> / <body> 下的 <script type="nebula"> 脚本块（type 必须是 nebula；嵌套在其它标签内部的不会被识别）；写在文件末尾（</html> 之后）的脚本会被解析器并入 body，同样有效，参考 public/404.wn；
3. 每个脚本块执行完即从页面中移除，不会出现在最终 HTML 里；块内可用完整 Nebula 语法（变量赋值、判断 / 循环框、[函数] 定义、内置函数与对象方法）；
4. <script type="nebula"> 是「服务端 Nebula 脚本」，不是 JavaScript：标签名虽然叫 script，但它由 Nebula 在服务端执行、执行完即被移除，浏览器看不到它，也拿不到它的内容。禁止在块里写 JavaScript（let / const / var / function / 箭头函数 / document / window / console / alert / fetch / setTimeout / addEventListener 等一律不行），也禁止用 document.write / console.log / 弹窗输出——写了不会报错，但只会被当成普通文本或被丢弃，不会执行，页面毫无效果（典型表现是白屏、或原样显示一行代码）。块里要输出内容只有两种办法：写裸文本，或赋值后用 {{.键}} 在 HTML 里取；
5. 需要浏览器端 JavaScript（点击交互、canvas 绘制、动画、定时刷新）时，另外写一个不带 type 属性的普通 <script>（或 <script type="text/javascript">）：Nebula 不会执行这种块，会把它原样留在最终 HTML 里交给浏览器运行。两种块各写各的，不要混写，尤其不要用 <script type="nebula"> 把 JS 包起来（那样 JS 完全不生效）；普通 <script> 里要用脚本产出的数据，同样写 {{.键}}（Go 模板会按 JS 上下文转义）。

三、输出与模板渲染
1. 所有脚本块执行完毕后，整份 HTML 会用 Go html/template 渲染一次，把 {{.键}} 替换成脚本产出的数据；
2. 数据来源按 <script> 的 id 区分：
   带 id：data[id] = 该脚本块的执行输出，模板里写 {{.id}}（如 <script type="nebula" id="版本">版本:1.0.0
%版本%</script> → {{.版本}} 得到 1.0.0）；
   不带 id：该脚本块产生的变量并入模板数据，模板里写 {{.变量名}}；
3. 只有「赋值」产生的变量才会进模板数据；脚本块里的裸文本只是输出，不会变成模板键；
4. 模板键写错不会报错、只会渲染成空——页面出现大片空白时，先核对变量名与 id 是否一致；
5. 模板数据只能是文本：{{.键}} 一律会被 HTML 转义后插进页面。二进制数据（如 $画布.获取$ 返回的 PNG/JPEG 字节）无法这样显示——放进文本位会变成乱码，放进 <img src="{{.键}}"> 又会被 Go html/template 的 URL 过滤器换成 #ZgotmplZ（它只放行 http/https/mailto，data: 一律拒绝）。因此 .wn 里禁止用 Nebula 画布产图当页面内容，也禁止写 图:$画布.获取 png$ 这种赋值后不再使用的死代码（页面不会出现任何图像）；页面上要画图形请直接用 HTML/CSS，或用浏览器原生 <canvas> + JS 绘制（canvas 绘制用的 JS 必须写在普通 <script> 里，写进 type="nebula" 块不会执行）。

四、完整示例
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>我的站点</title>
</head>
<body>
    <h1>你好，{{.昵称}}</h1>
    <p>版本信息：v {{.版本}}</p>
<script type="nebula">
昵称:$GET 名字 访客$
</script>
<script type="nebula" id="版本">
版本:1.0.0
%版本%
</script>
</body>
</html>
（{{.昵称}} 来自无 id 脚本块里赋值的变量，{{.版本}} 来自 id 为「版本」脚本块的输出。）
需要浏览器端交互 / 动画时另写一个普通 <script>（不带 type="nebula"），例如 <script>document.title = {{.版本}};</script>——这种块 Nebula 不执行，浏览器才会执行它。

五、HTTP 相关
1. .wn 被访问时可用 $GET key 默认值$ 读查询参数、$POST key 默认值$ 读表单 / JSON 参数、$全局变量 访问数据$ 取整个请求信息（路径 / 来源 / 请求头 / IP / Host / POST / POSTFile）；
2. 响应头用 $设置头部 key value$；响应状态用 $全局变量 响应状态 404$；额外头部用 $全局变量 输出头部 {"Location":"https://..."}$；
3. 不要用 $全局变量 输出类型$ 设内容类型（这条路径没有读取它），要改 Content-Type 就用 $设置头部 Content-Type ...$（router.n 已默认设为 text/html;charset=UTF-8）。

六、注意事项
1. .wn 不能承载机器人功能：机器人只执行 <账号路径>/dic/ 下的 .n，用户发消息不会触发 .wn；
2. 需要 JSON / 纯文本接口时改用被 HTTP 访问的 .n（以 Main 为触发词），不要用 .wn 硬凑，见「API词库开发」技能；
3. 内置函数与对象方法的准确用法一律以内置文档（read_dic_doc，按需读取对应篇章）为准（语法规则见「词库语法结构」技能），不确定就查证或向用户确认，不要往文件里塞试探代码；
4. 本智能体只负责 .wn：若当前任务关联的文件是机器人 .n 之类的非网页文件，不要把它改写成网页词库，应说明冲突后改为在网站根目录 public/ 下新建 / 修改 .wn 文件；反过来，也绝不能把网页需求写成 .n（无触发词的 .n 根本不生效，用户发消息也不会触发）；
5. 改完必须验证：用 save_dic 保存 .wn 后，调用 run_web_dic 运行一次，检查返回的最终 HTML 里脚本块已消失、{{.键}} 已被真实数据替换；若渲染结果是空白或模板键没被替换，先核对 id / 变量名再重新保存与运行，不要凭「保存成功」就汇报完成。
