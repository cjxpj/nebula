【机器人词库开发（.n / 消息触发）】
目标：编写机器人词库——先写菜单（功能导航），再逐个实现各功能的触发词与正文。写代码前读取「词库语法结构」技能。

一、文件与位置
1. 机器人词库是 .n 文件，放在机器人账号路径下的 dic/ 目录（如 private/bot/qq/dic/）：只有 .n 会被执行，同目录的 .md / .txt / .json 会被跳过，可放心放说明文档；
2. 建议按功能拆分文件（如 五子棋.n、签到.n），不要把大量触发词堆在同一个文件里。

二、先写菜单（功能导航）
1. 用普通触发词 菜单（推荐）/ 功能 / 帮助 之一作为导航入口（三者同类，选一个即可，不要重复写），正文必须逐个列出「功能 → 用户该发什么指令」：
菜单
可用功能：\r
五子棋 —— 发送「五子棋」开始\r
钓鱼 —— 发送「钓鱼」开始\r
签到 —— 发送「签到」领取
2. 多行内容要在每行行尾加 \r 换行（最后一行不加），否则各正文行会被直接拼接成一行；
3. 菜单不要写进 Main：机器人收到消息是按文本匹配触发词的，匹配不到就不回复，永远不会落到 Main；Main 只是「无参数主动执行入口」（$执行词库$、定时任务等）的专用触发词，功能 / 娱乐类词库一律不写 Main；
4. 菜单宣传的每个指令都必须真实存在对应触发词，改完菜单后逐一核对，避免「菜单写了但发指令没反应」。

三、触发词写法
1. 触发词独占一行、正文紧跟其下；正文行之间不能有空行（空行会立即结束当前词条，并让后续代码脱离词块）；
2. 精确匹配：触发词写成完整文本（如 签到、下子），用户消息需与之完全相同；
3. 带参数与正则：消息按空格切分后用 %参数0%（第 1 个词）、%参数1%（第 2 个词）…；含正则元字符即按正则匹配（如 下子 (.+)、测试 .+），捕获组用 %括号0%（整体）、%括号1%（第一组）；正则建议收敛为 ^触发词$ 之类，避免误匹配；
4. 事件触发词（由框架派发，不是用户消息）：[群事件]群成员进群、[群事件]群成员退群、[群事件]机器人进群、[群事件]机器人退群、[群事件]入群申请、[内部]好友添加、[内部]好友删除、[按钮事件]<data>、[菜单事件]<功能ID>、[系统]启动；
5. 消息上下文变量：%QQ% / %群号% / %昵称% / %管理%（1 群主、2 管理员、0 成员）/ %MsgId%；事件还会注入 %成员% / %操作者% / %事件类型% / %来源%，入群申请另有 %申请理由% / %申请问题% / %申请ID% 等。

四、正文与回复
1. 机器人场景下，词条正文直接输出的文本会自动作为回复发给用户，不需要 $发送文本$；只有「额外再补发一条」时才用 $发送文本$ / $发送MD$ 等主动发送函数，且需在文件头部 #引入=@机器人；
2. $GET$ / $POST$ 在机器人词库中不可用（没有 HTTP 上下文），读取用户输入只能用 %参数N% / %括号N% 与消息变量；
3. 数据持久化优先用 $读 路径 键 默认值$ / $写 路径 键 数据$（存到 database/ 目录），路径按「游戏 / 功能 → 分类 → 用户」分层，推荐 <游戏名>/<分类>/<QQ>.txt；余额、排行、多账号等关系型数据才用 db_* 系列。

五、娱乐 / 功能词库的组织方式
1. 一个功能一组触发词：如棋盘、落子、悔棋、重置各写一个触发词，共用逻辑抽成 [函数|N]名称，触发词正文里用 $函数名 参数$ 调用（函数定义可放在文件任意位置，在触发词之后定义同样有效）；
2. 需要跨消息保持的状态（棋盘、背包、积分）必须落盘：用 $读$ / $写$ 或 JSON（$JSON存$ / $JSON解析$），不要指望全局变量在两次消息之间还在；
3. 输出多行文本用 \r 换行，长内容用 文本>...<文本 结构化书写。

七、注意事项
1. 不要给机器人词库写 Main、也不要把菜单 / 使用说明塞进 Main；
2. 不确定的内置函数、对象方法或参数用法，先用 read_dic_doc 查内置文档（按需读取对应篇章）或向用户确认，禁止往词库里批量写试探词条。
