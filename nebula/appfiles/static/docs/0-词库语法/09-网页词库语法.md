# 网页词库语法

网页词库（WebNebula，后缀 `.wn`）是「HTML 容器 + 内嵌执行块」：执行块里写的仍是本系列 01~08 讲的 Nebula 语法，只是文件形态、执行时机与输出方式跟 .n 不同。`.wn` 没有触发词，页面被访问时执行块自动依次执行，最后整份 HTML 用 Go 模板渲染一次并作为响应返回。

## 一、文件与位置

1. `.wn` 是 UTF-8 文本，整体就是一份完整 HTML（`<!DOCTYPE html>` … `</html>`），Nebula 语句必须写在执行块里，块外只写普通 HTML；浏览器最终看到的是执行块跑完、`{{.键}}` 被替换后的页面；
2. 默认放在网站根目录（`%网站根目录%`，即 public/）下，访问路径即文件路径：`public/index.wn` ↔ `/index.wn`（默认首页）、`public/about.wn` ↔ `/about.wn`；不含任何执行块的 `.wn` 就是一份纯静态 HTML 页面，同样能被访问；
3. 请求由 system/router.n 路由：命中 `.wn` 时先 `$设置头部 Content-Type text/html;charset=UTF-8$` 再 `$执行网页词库文件 <路径>$`；文件不存在时输出 `public/404.wn`（并置响应状态 404）；命中 `.n` 时以 Main 为触发词执行，见「API词库开发」技能；
4. `.wn` 不能承载机器人功能：机器人只执行 `<账号路径>/dic/` 下的 `.n`，用户发消息不会触发 `.wn`；需要 JSON / 纯文本接口时改用被 HTTP 访问的 `.n`。

## 二、执行块

执行块有两种写法，块内都写 Nebula 语法，优先用第一种：

1. `<?n ... ?>` 内联块（推荐）：就地执行，结果原样插回块所在的位置，所以可以写在 HTML 的任意位置（段落里、行内都行）；块内的裸文本会成为该处的页面内容，也可以直接输出 HTML 片段。写法固定为「`<?n` 单独占一行（也可以紧跟在 HTML 之后，如 `<p>前缀<?n`）+ 块内每条语句各占一行 + `?>` 收尾（`?>` 后面可以直接跟同一行的 HTML，如 `?></p>`）」，块内按行解析，多条语句不要挤在同一行；标记本身不会出现在最终页面里；
2. `<script type="nebula">` 脚本块（兼容写法，适合大段多行脚本）：只识别直接挂在 `<head>` / `<body>` 下的块（type 必须是 nebula），嵌套在其它标签内部的不识别；写在 `</html>` 之后的脚本会被解析器并入 body，同样有效（可参考 public/404.wn）；块执行完即从页面中移除，不会出现在最终 HTML 里；带 id 的脚本块把整块输出存进 `{{.id}}`，不带 id 的脚本块把块里赋值的变量并入模板数据（不带 id 的脚本块只能有一个，否则变量互相覆盖）；
3. 两种块可以混用在同一个文件里，块内能用完整 Nebula 语法（变量赋值、`[函数]` 定义、判断 / 循环、内置函数与对象方法）；
4. 漏写 `?>` 的 `<?n` 不是执行块：运行时整块不执行，且它之后的内容都会原样输出到页面，表现为「代码被当成正文显示出来」。

## 三、执行顺序与作用域

1. 执行分两轮：先按出现顺序跑完文件里所有 `<?n ... ?>` 内联块（在 HTML 解析之前，结果先插回原文），再按文档顺序跑所有 `<script type="nebula">` 脚本块；
2. 每个执行块独立作用域：块里赋的变量只在当前块内有效，后面的块读不到；`$全局变量 响应状态$` / `$设置头部$` 这类页面级上下文仍跨块共享；需要跨块传递数据就写在同一块里；
3. 块内首尾空白会被裁掉，所以 `<?n` 之后要换行再写语句：块内首行是空行时会被当成「头部结束」，块里的语句不会执行（脚本块同理）。

## 四、输出与模板渲染

1. 所有执行块跑完后，整份 HTML 会用 Go html/template 渲染一次，把 `{{.键}}` 替换成脚本产出的数据；
2. 脚本块按写法提供模板数据：
   - 带 id 的脚本块：该块的执行输出存进 data[id]，模板里写 `{{.id}}`。如 `<script type="nebula" id="发布号">发布号:1.0.0` + 换行 + `%发布号%</script>` → 页面写 `{{.发布号}}` 得到 1.0.0；
   - 不带 id 的脚本块：块里「赋值」的变量并入模板数据，页面写 `{{.变量名}}`。不带 id 的脚本块只能有一个（多个会互相覆盖）；
   内联块就地输出：它块里赋值的变量不进模板数据，页面不能用 `{{.变量名}}` 取；内联块的裸文本已经就地输出，也不需要再取；
3. 模板键只来自脚本块（带 id 的是 `{{.id}}`，不带 id 的是 `{{.变量名}}`）；内联块里赋的变量、以及裸文本，都不进模板数据；
4. 模板键写错不会报错、只会渲染成空——页面出现大片空白时，先核对 id / 变量名是否与脚本块一致；
5. 别拿内置「魔术变量」当自己的变量名：版本、时间、时间戳、空格、换行、系统 等由运行环境内置提供，优先级高于你自己赋的值——写成 版本:1.0.0 再取 `%版本%`，拿到的仍是程序版本号。自己的数据请另起名字（如 发布号、站点名）；
6. 模板数据只能是文本，`{{.键}}` 一律会被 HTML 转义后插进页面，二进制数据（如 `$画布.获取$` 返回的 PNG / JPEG 字节）不能整串丢给模板；`.wn` 里要用画布产图，写法见「绘图与图片处理」篇（模板里字面写 `data:image/png;base64,` 前缀、变量只放 base64 正文，或落盘成静态文件后用 `<img src="/out.png">`）。

## 五、HTTP 相关

1. `$GET key 默认值$` 读查询参数、`$POST key 默认值$` 读表单 / JSON 参数（第二个参数可省略，读不到时返回空字符串）、`$全局变量 访问数据$` 取整个请求信息（路径 / 类型 / 查询参数 / 请求头 / IP / Host / POST / POSTFile）；
2. 响应头用 `$设置头部 key value$`；响应状态用 `$全局变量 响应状态 404$`（不设时默认 200）；额外头部用 `$全局变量 输出头部 {"Location":"https://..."}$`，COOKIE 用 `$全局变量 COOKIE [...]$`；
3. 不要用 `$全局变量 输出类型$` 设内容类型（这条链路不读它），要改 Content-Type 就用 `$设置头部 Content-Type ...$`（router.n 已默认设为 text/html;charset=UTF-8）。

## 六、与 JavaScript 的边界

1. 执行块是「服务端 Nebula 脚本」，不是 JavaScript：脚本块虽然叫 script，但它由 Nebula 在服务端执行、执行完即被移除，浏览器看不到它，也拿不到它的内容；
2. 禁止在执行块里写 JavaScript（let / const / var / function / 箭头函数 / document / window / console / alert / fetch / setTimeout / addEventListener 等一律不行），也禁止用 document.write / console.log / 弹窗输出——写了不会报错，但只会被当成普通文本或被丢弃，页面毫无效果（典型表现是白屏、或原样显示一行代码）；
3. 需要浏览器端 JavaScript（点击交互、canvas 绘制、动画、定时刷新）时，另写一个不带 type 的普通 `<script>`（或 `<script type="text/javascript">`）：Nebula 不会执行这种块，会把它原样留在最终 HTML 里交给浏览器运行；要在里面用脚本产出的数据，同样写 `{{.键}}`（Go 模板会按 JS 上下文转义）；两种块各写各的，不要用 `<script type="nebula">` 或 `<?n ... ?>` 把 JS 包起来（那样 JS 完全不生效）。

## 七、完整示例

```
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>我的站点</title>
</head>
<body>
    <h1>你好，{{.昵称}}</h1>
    <p>版本信息：v <?n
发布号:1.0.0
%发布号%
?></p>
<script type="nebula">
昵称:$GET 名字 访客$
</script>
</body>
</html>
```

`<p>` 里的内联块就地输出 1.0.0；脚本块里 `昵称:$GET 名字 访客$` 赋值，页面用 `{{.昵称}}` 取到（`$GET 名字 访客$` 读查询参数 名字，读不到就用 访客）。示例里没用 `{{.版本}}`，因为 版本 是内置魔术变量。

再看一个三种块混用的例子，注意各自的数据流向（无 id 脚本块、带 id 脚本块、内联块同时出现）：

```
<div>
    {{.a}}
    {{.b}}
    <?n
        循环>i=2
            <h3>c</h3>
        <循环
    ?>
</div>
<script type="nebula">
    a:<h1>👉</h1>
</script>
<script type="nebula" id="b">
    <?n
    $复读 b$
    ?>
</script>
```

渲染结果（脚本块已被移除）：

```
<div>
    &lt;h1&gt;👉&lt;/h1&gt;
    bb
    <h3>c</h3>
    <h3>c</h3>
</div>
```

- 不带 id 的脚本块 `a:<h1>👉</h1>` 给变量 `a` 赋值，`{{.a}}` 取到它；模板数据一律 HTML 转义，所以 `<h1>👉</h1>` 被转成 `&lt;h1&gt;👉&lt;/h1&gt;`，页面显示的是字面文本而不是标题；
- 带 id 的脚本块 `id="b"`：块里的 `<?n $复读 b$ ?>` 内联块先执行（`$复读 b$` 不带次数默认重复 2 次），输出 `bb` 填回脚本块正文，于是整块输出 `bb` 存进 `{{.b}}`；
- `<div>` 里的内联块 `循环>i=2 ... <循环` 循环 2 次，每次输出一行 `<h3>c</h3>`，这是原始 HTML 就地输出，浏览器直接渲染成两个标题 c，不做转义。

## 八、编辑与校验

1. 保存时编辑器会按 HTML 结构自动缩进：`<?n ... ?>` 内联块与脚本块的正文会按 Nebula 块结构排版，两种块的行首缩进在解析前都会被自动裁掉，所以块内不必刻意顶格写；确实要保留行首空白时（例如文本框内容本身带缩进），用 `//@关闭缩进` 与 `//@启用缩进` 把这几行夹起来；
2. 词库调试页运行 `.wn` 会返回渲染完成的整页 HTML，默认渲染预览，可切换查看 HTML 源码；
3. 保存 `.wn` 时会对执行块做变量检查与模板键核对，并给出 warnings（「变量赋值后未被使用」= 死代码、「模板键不存在」= 页面渲染成空），有 warning 应逐条修掉；模板键没被替换或页面空白时，先核对 id / 变量名再重新保存与运行。
