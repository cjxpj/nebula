# 触发词与取值

1. 触发词就是执行入口，且入口范围按词库类型不同：机器人词库靠用户消息匹配触发词执行，写出来的任意触发词都能被唤起；API 词库（被 HTTP 访问）则只有 Main 会被执行，其他触发词走不到（详见「机器人词库开发」「API词库开发」技能）；
2. 任何情况下触发词都必须独占一行，且其上方必须有一个空行与头部或上一条词条分隔：空行是词条的硬边界，贴着上一条正文或头部写会被并入上一条（该触发词完全失效），贴在头部后面则会被并入头部；若其上方写 // 注释，注释要紧贴触发词、注释上方同样要留一个空行（即「空行 → 注释 → 触发词」，注释与触发词之间不能有空行）；文件第一个词条是触发词时，其上方同样要有一个空行（空行之前视作空头部）；头部（文件开头到第一个空行）是每次执行都会经过的中间件，文件第一行也属于头部、会被算入中间件执行；
3. 触发词不要默认写 Main：Main 只是「无参数主动执行入口」（网页被访问、定时任务、$执行词库$ 等主动执行场景）的专用触发词，功能 / 娱乐类词库靠用户发消息唤起（如「五子棋」「钓鱼」「签到」），一律不写 Main，写了是死代码（机器人收到消息是按文本精确/正则匹配触发词，匹配不到不回复，永远轮不到 Main），还容易把使用说明、菜单等不该展示的内容塞进去；用户没有明确指定触发词时，按该词条功能自行命名一个简短、贴合语义的触发词（如 画九宫格、签到、下子），并保证词条之间触发词不重复；只有用户明确要求用 Main、或确属主动执行入口时才写 Main；
4. 触发词即用户消息文本，行首 [类别] 前缀决定角色：[函数]名称、[内部]名称（用 $回调 名称$ 触发）、[函数:类名]方法、[内部:类名]方法；无前缀即普通触发词；
5. 触发词按正则匹配（不含正则元字符时按纯文本全等匹配）。%参数0% 是消息按空格切分后的第 1 个词（%参数N% 即第 N+1 个词）；%括号0% 是整体消息文本，%括号N% 是正则第 N 个捕获组（从 1 开始）；多个触发词匹配同一输入时默认只执行第一个命中的词条，在正文里调用无参函数 $继续执行$ 按正常触发词匹配规则（纯文本优先、正则按序）只执行紧邻的下一个命中的词条（只往下走一个；要多级往下，需每个词条里都调用 $继续执行$）；$继续执行$ 仅允许在正文触发词（无 [类别] 前缀的普通触发词）下使用，在 [函数]/[内部]/[函数:类名] 等方法里调用会直接报错；
6. 普通词条与函数中直接输出的文本就是回复内容，无需再调用 $发送文本$。
