# 流程控制

## 块：开启行 → 闭合行

| 块 | 开启行 | 闭合行 |
| --- | --- | --- |
| 判断框 | `如果>条件` | `<如果` |
| 匹配框 | `匹配>表达式` | `<匹配` |
| 循环框 | `循环>i=次数`、`循环>i=起始~结束`、`判断循环>条件` | `<循环` |
| 遍历框 | `遍历>键,值=JSON` | `<遍历` |
| 文本框 | `文本>`、`纯文本>` | `<文本` |
| 函数框 | `变量:函数>`、`变量:执行函数>` | `<函数` |
| JSON 框 | `JSON>变量={}`、`JSON>[]` | `<JSON` |

- 闭合行一律**不带 `>`**：写 `<循环`、`<如果`。写成 `<循环>` 不会被识别，会报「循环框未闭合」。
- 嵌套时每层开启各要一条对应闭合行，闭合行数必须等于开启行数。
- 块的开启行、闭合行必须紧贴代码，行尾不要加 `//` 注释。

## 判断框 vs 行内判断（两种写法，不能混用）

- 判断框：`如果>条件` … `>否则如果:条件` … `>否则` … `<如果`
- 行内判断：`如果:条件` … `否则如果:条件` … `否则` … `如果尾`

判断的开启符号写 `>` 还是 `:` 就决定了是哪一种：`如果>…` 必须用 `<如果` 收尾，`如果:…` 必须用 `如果尾`（或 `返回`+`如果尾`）收尾。

**开启符号写错是最常见的坑**：把 `如果>` 误写成 `如果:`、却仍用 `<如果` 闭合时，整块不会被识别——闭合行会被当普通文本输出、块内语句只按顺序执行一遍，功能静默错乱且不报错。

## 循环

- `循环>i=次数`：i 从 1 递增到次数；`循环>i=起始~结束`：含两端；`判断循环>条件`：while。
- 范围分隔符只有 `~`（写 `0~14`）；写成 `..` 会报「循环框未闭合」。
- `循环>i`（不带次数）是死循环，禁止；循环必须有退出条件。
- 循环体内可用：`>跳过`（跳过本轮剩余语句）、`>中断` / `>终止循环`（退出循环）、`>终止遍历`（退出遍历）。

## 条件与跳转

- 条件判断可用 `$判断 a 等于 b$` 返回 true/false；`如果>` 的条件支持 `==` `!=` `>` `<` `>=` `<=`、`且`/`或`/`!` 与括号（数字按数值比较，不会退化成字符串比较）。
- `>终止` 只终止「当前执行体」：写在词条正文里终止本次词库执行，写在 `[函数]` 里只终止该函数、调用方继续往下执行；`>终止 文案` 终止并把文案一起输出。
- `>返回` 是 `>终止` 的同义词（`>返回 文案` 同 `>终止 文案`），语义完全一致；积木工具箱中「返回」与「终止执行体」两个积木分别对应二者。
- `$跳行 <行号>$` 绝对跳转：行号可为字面量、`%变量%` 或 `[...]`，从 1 起（如 `$跳行 [%行数%+1]$`）；跳到不存在的行号则不跳转。
- `$STOP$` 会退出整个程序进程，一律禁用。

## 回调与测试框

- 回调：`$回调 名称$` 触发 `[内部]名称`（内部词条可放在任意触发词下，缩写 `[L]`）；回调名支持正则，捕获组进 `%括号N%`、空格分隔的参数进 `%参数N%`；类内写 `[内部:类名]名称`，类方法里 `$回调 名称$` 只在实例内生效。回调内能读调用方的变量，但回调内的赋值不回传调用方，要拿结果只能用 `变量:$回调 名称 ...$` 捕获回调的输出文本。
- 测试框（报错捕获，仅赋予值形式）：`变量:测试> … <测试`。框内语句照常执行、输出直接到外层；执行到某行报错时立即终止框内后续语句、把「函数自带的原始报错信息」赋给变量（报错前的输出已保留），然后继续执行 `<测试` 之后的语句、不中断整个词库；无报错时变量为空。`>终止` 仍会向上终止、不被捕获；主动抛错用 `$报错$`（默认文案「主动报错」）或 `$报错 错误信息$`。
