# 高频易错点

1. [函数] 未声明参数规则（[函数|N]）时不能带参调用；形参只能靠 %参数1%…%参数N% 取，定义处 ->变量1,变量2 只是传出列表，不是形参；
2. 文本块（文本>、三引号文本框、变量:{、变量:[）里的 $函数$ 不会执行，会原样输出；
3. `$` 必须首尾成对，漏哪一头都是「静默不生效」：漏开头 `$`（写成 `玩家.存 ...$`）调用不执行；**漏结尾 `$`（写成 `结果:$JSON解析 %距离% 99`）调用同样不执行、赋值落空，整行被当普通文本输出（%变量% 照常插值）且不报错**。写完先数行内 `$` 个数是否为偶数；
4. 块开启行必须带 `>`：`如果>`、`匹配>`、`循环>`、`判断循环>`、`遍历>`、`文本>`、`函数>`、`JSON>`。把 `如果>` 误写成 `如果:` 就变成另一种写法「行内判断」（要用 `如果尾` 收尾），若再配 `<如果` 闭合则整块不被识别——闭合行被当普通文本输出、块内语句只顺序执行一遍，静默错乱且不报错；
5. 不要套用其它语言写法：.n 没有 def/class/for/while/return 等关键字，也没有字符串字面量类型，一切靠「键:值」「%变量%」「$函数 参数$」与 [类别] 触发词前缀；
6. 不要给类实例编造方法名或参数个数：以文档或已有示例为准，拿不准就如实说明「不确定」并请用户确认，禁止用一串坐标/数字硬凑参数（如给只收颜色的 $画布.设置颜色$ 传矩形参数）；
7. 写码前必须查文档求证：函数名、参数个数、返回值、块语法一律以本主题文档或已编译通过的示例为准；不要凭记忆、也不要凭前几轮对话里读过的印象拼语法（对话历史会被压缩），查不到就如实说明不确定，禁止凭印象书写或编造；
8. 文本框可以赋予值，多行内容别逐行累加：`变量名:文本>行间分隔符` 起头（等价写法 `文本>变量名=行间分隔符`）、内容行紧贴、`<文本` 收尾，整块内容赋给变量、本框不输出（行间默认不插字符，要换行写 %换行%），之后用 %变量名% 读取；多行 HTML / 长文本一律用这种写法一次赋值，不要写「变量: 置空 + 变量+: 逐行累加」；内容要保留 %变量% 原样不插值时用 `变量名:纯文本>...`。
9. 禁止乱换行与乱空格：正文行与行一律紧贴，不得插入空行（空行会截断词条或块结构），也不要用空行、缩进去做「分段」「美化」；%变量%、$函数 参数$、键:值 之间只保留语法要求的单个空格，行首 / 行尾不要补空格，`[...]` 表达式内不写空格（写 [1000*%秒%]，不写 [1000 * %秒%]）；行首缩进不必自己对——保存时会按 .n 块结构 / .wn HTML 结构自动格式化（.wn 的 `<?n ... ?>` 内联块与 `<script type="nebula">` 脚本块正文同样会被自动排版，行首缩进在解析前会被裁掉）；确实要保留行首空白的行用 `//@关闭缩进` 与 `//@启用缩进` 夹起来。
