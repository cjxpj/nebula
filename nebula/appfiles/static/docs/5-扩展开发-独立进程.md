# 扩展开发（独立进程）

> 独立进程扩展是**任意语言编写的独立可执行程序**。主程序在启动时按扩展目录下的 `plugin.json` 启动它，并通过本地 TCP（`127.0.0.1`）以「换行分隔的 JSON」协议与之通信，把其声明的函数注册到词库，词库可用 `$函数名$` 调用。适合需要**进程隔离**（扩展崩溃不影响主程序）、**使用任意语言**（Python/Node/Go/…）或**依赖较重运行时**的场景。

与动态库（`.dll`/`.so`）扩展的取舍：

| 维度 | 动态库扩展 | 独立进程扩展 |
| --- | --- | --- |
| 语言 | 需导出 C ABI（C/C++/Rust 等） | 任意语言，只要能起本地监听 |
| 性能 | 进程内直接调用，开销极低 | 序列化 + 往返，单次约几十微秒 |
| 隔离性 | 与主程序同进程，崩溃会波及主程序 | 独立进程，崩溃不影响主程序 |
| 依赖 | 需匹配主程序运行库与架构 | 自带运行时即可 |
| 适用 | 高频调用、追求原生性能 | 低频/重依赖/需隔离/多语言 |

> 追求极致性能时选动态库；需要隔离或多语言时选独立进程。二者可同时使用，互不影响。

## 目录结构

主程序启动时扫描 `<数据目录>/private/plugins/`，识别两类条目：动态库文件（`.dll`/`.so`），以及**内含 `plugin.json` 的子目录**（独立进程扩展）。一个独立进程扩展的目录形如：

```
private/plugins/
└── 我的扩展/
    ├── plugin.json     # 清单：如何启动、启动什么
    └── main.py         # 扩展程序（任意语言）
```

## plugin.json

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 否 | 扩展名，仅用于日志；缺省取目录名 |
| `command` | string | 是 | 可执行文件或解释器；相对路径优先相对插件目录查找，找不到再回退到 `PATH` |
| `args` | []string | 否 | 启动参数 |
| `env` | object | 否 | 附加环境变量 |
| `port` | int | 否 | 固定监听端口；`0` 或缺省表示由主程序自动分配空闲端口 |
| `timeout` | int | 否 | 单次调用超时（毫秒）；`0` 表示不限时 |

示例（Python）:

```json
{
  "name": "Python 示例扩展",
  "command": "python",
  "args": ["main.py"]
}
```

示例（Go，演示用 `go run`；生产环境建议先 `go build -o ext-go.exe`，再把 `command` 改为 `ext-go.exe`）:

```json
{
  "name": "Go 示例扩展",
  "command": "go",
  "args": ["run", "main.go"]
}
```

## 通信协议

主程序启动扩展进程时，会通过环境变量 **`NEBULA_PLUGIN_PORT`** 注入监听端口（若 `plugin.json` 指定了固定 `port` 则用该值）。扩展须监听 `127.0.0.1:<端口>`，接受主程序的一条长连接，收发 **UTF-8 编码、以换行（`\n`）分隔的 JSON 消息**（每行一条）。

请求（主程序 → 扩展）：

```json
{"id":1,"type":"list"}
{"id":2,"type":"call","fn":"示例加法","args":["1","2"]}
{"id":0,"type":"close"}
```

响应（扩展 → 主程序，`id` 必须与对应请求一致）：

```json
{"id":1,"type":"list","funcs":[{"name":"示例加法","l":"2"}]}
{"id":2,"type":"call","result":"3"}
{"id":2,"type":"call","error":"出错信息"}
```

消息类型：

- `list`：握手。主程序连接后立即发送，扩展须在 `funcs` 中返回其注册的字典函数列表（`name` 函数名、`l` 参数规则，规则同内置函数：`"0"` 无参、`"1|2"` 一或两个参数、`"2.."` 两个及以上参数）。
- `call`：调用函数。`fn` 为函数名，`args` 为已转成字符串的参数数组；成功用 `result` 返回结果字符串，失败用 `error` 返回错误信息。
- `close`：主程序要求扩展退出。

> **主程序对单个扩展串行调用**：收到上一条响应后才发送下一条请求。扩展只需按「读一行、写一行」处理即可，无需考虑并发。

## 生命周期

- **加载**：主程序启动时扫描 `private/plugins/`，逐个启动扩展进程、连接端口并完成 `list` 握手；启动后等待扩展监听端口的超时为 10 秒（进程若提前退出会立即报错返回）。
- **调用**：词库执行 `$函数名$` 时，主程序把参数转为字符串经 `call` 发送，并把 `result` 作为函数返回值。
- **卸载**：主程序退出或关闭扩展时，先发送 `close` 并关闭连接；扩展应随即自行退出，若 2 秒内仍未退出，主程序将强制结束该进程。
- 扩展仅在**启动时加载一次**，运行期不热更新，修改后需重启主程序生效。

## 参数与返回值

- 参数：词库参数由主程序转为字符串（`string` → 原文、数字 → 十进制、布尔 → `true`/`false`）后放入 `args` 数组。
- 返回值：响应中的 `result` 字符串作为词库函数结果；未提供 `result` 视为空字符串。
- 出错：响应中的 `error` 作为调用错误抛出，词库可据此处理。

## 示例工程

源码仓库 `examples/` 目录下提供两个可直接运行的示例，把目录整体复制到 `<数据目录>/private/plugins/` 后重启主程序即可：

- `examples/ext-go/`：Go 示例（`main.go` + `plugin.json`），标准库实现，无第三方依赖。
- `examples/ext-python/`：Python 示例（`main.py` + `plugin.json`），标准库实现。

两个示例均注册了「示例测试」「示例回显」「示例加法」「示例报错」四个函数，可用于对照实现自己的扩展。

## 注意事项

- **函数名不可与内置函数或其他扩展冲突**：冲突时会在日志报错并跳过，不会覆盖内置函数。
- **扩展与主程序同用户权限运行**：属于可信代码，只安装来源可信的扩展；端口仅绑定 `127.0.0.1`，请勿让扩展把该端口暴露到外部网络。
- **接口为字符串传参**：无法直接传递复杂对象；需要结构化数据时，可在扩展侧自行解析/构造 JSON 或自定义格式。
- 扩展函数会自动出现在管理面板的词库补全列表中（`ListFuncs()` 实时返回），无需手动同步前端。
- 若扩展启动失败或握手失败，会在日志中报错并跳过该扩展，不影响主程序与其他扩展。
