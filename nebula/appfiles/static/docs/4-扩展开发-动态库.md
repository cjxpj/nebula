# 扩展开发（动态库）

> 扩展是用 C 编写、编译为 `.dll`（Windows）或 `.so`（Linux/Android/鸿蒙）的原生动态库。主程序在**运行时**加载，通过固定 C ABI 枚举并调用其中注册的字典函数，词库可用 `$函数名$` 调用。适合需要原生性能、调用第三方 C/C++ 库，或希望**不重新编译主程序**即可扩展函数的场景。

## 标准接口

扩展需导出以下固定符号（C 链接，C++ 下用 `extern "C"` 包裹）：

| 符号 | 签名 | 说明 |
| --- | --- | --- |
| `ext_init` | `int ext_init(void)` | 初始化，返回 `0` 成功、非 `0` 失败 |
| `ext_close` | `void ext_close(void)` | 退出清理 |
| `ext_count` | `int ext_count(void)` | 注册的函数数量 |
| `ext_name` | `const char* ext_name(int index)` | 第 `index` 个函数名（UTF-8） |
| `ext_l` | `const char* ext_l(int index)` | 第 `index` 个函数的参数规则 `L`（如 `"0"`、`"1|2"`、`"2.."`） |
| `ext_call` | `const char* ext_call(const char* name, const char* const* args, int argc, const char** err)` | 调用函数；成功返回结果字符串（可为 `NULL` 表示空串）并把 `*err` 置为 `NULL`，失败返回 `NULL` 并把 `*err` 指向错误信息 |

> 返回字符串的缓冲区须在下一次调用本扩展或 `ext_close` 之前保持有效；服务端会立即复制，用单个静态缓冲区即可。服务端串行调用扩展，无需考虑并发。

## 示例

```c
#include "ext.h"

static const struct { const char* name; const char* l; } funcs[] = { {"扩展测试", "0"}, {"扩展回显", "1"}, {"扩展加法", "2"}, {"扩展报错", "0"} };
static char buf[4096];
int ext_init(void) { return 0; }
void ext_close(void) {}
int ext_count(void) { return (int)(sizeof(funcs) / sizeof(funcs[0])); }
const char* ext_name(int i) { return (i >= 0 && i < ext_count()) ? funcs[i].name : NULL; }
const char* ext_l(int i) { return (i >= 0 && i < ext_count()) ? funcs[i].l : NULL; }
const char* ext_call(const char* name, const char* const* args, int argc, const char** err) {
    *err = NULL;
    if (strcmp(name, "扩展测试") == 0) { snprintf(buf, sizeof(buf), "扩展加载成功"); return buf; }
    if (strcmp(name, "扩展回显") == 0) { snprintf(buf, sizeof(buf), "%s", argc > 0 && args[0] ? args[0] : ""); return buf; }
    if (strcmp(name, "扩展加法") == 0) {
        double a = argc > 0 && args[0] ? atof(args[0]) : 0, b = argc > 1 && args[1] ? atof(args[1]) : 0;
        snprintf(buf, sizeof(buf), "%g", a + b); return buf;
    }
    if (strcmp(name, "扩展报错") == 0) { *err = "这是一个测试错误"; return NULL; }
    *err = "未知函数"; return NULL;
}
```

## 编译

在扩展工程目录编译（Windows 需 MinGW-w64 等 GCC 工具链）。`-Os` 优化体积、`-s` 去除符号、`--gc-sections` 剔除未使用代码，产物通常仅几 KB：

```
Windows：gcc -shared -Os -s -ffunction-sections -fdata-sections -Wl,--gc-sections -fno-asynchronous-unwind-tables -fno-stack-protector -o 我的扩展.dll main.c
Linux/Android/鸿蒙：gcc -shared -fPIC -Os -s -ffunction-sections -fdata-sections -Wl,--gc-sections -fno-asynchronous-unwind-tables -fno-stack-protector -o 我的扩展.so main.c
```

## 加载目录

主程序启动时自动扫描 `private/plugins/` 目录，加载其中的 `.dll`（Windows）或 `.so`（其他平台）：每个扩展通过 `ext_init` 初始化，`ext_count` / `ext_name` / `ext_l` 声明函数列表并据此注册字典函数，`ext_close` 对应退出清理。扩展仅在启动时加载一次、运行期不热更新，修改后需重新编译并重启主程序生效。

## 函数参数与返回值

- 参数：词库参数由服务端转为字符串（`string` → 原文、数字 → 十进制、布尔 → `true`/`false`），以 `const char* const* args` + `argc` 传入扩展。
- 返回值：扩展返回的字符串（`const char*`）作为词库函数结果，返回 `NULL` 表示空字符串。
- 参数数量规则 `L` 与内置函数一致：`"0"` 无参、`"1|2"` 一或两个参数、`"2.."` 两个及以上参数。

## 注意事项

- **函数名不可与内置函数或其他扩展冲突**：冲突时会在日志报错并跳过，不会覆盖内置函数。
- **接口为原生 C ABI、字符串传参**：参数与返回值均为字符串，无法直接传递复杂对象；需要结构化数据时可在扩展侧自行解析/构造 JSON 或自定义格式。
- 扩展函数会自动出现在管理面板的词库补全列表中（`ListFuncs()` 实时返回），无需手动同步前端。
- 主程序加载扩展在 Windows 用纯 Go 的 `LoadLibrary`（无需 CGO）；Linux/Android/鸿蒙需主程序以 CGO 构建（`dlopen`）；若主程序在无 CGO 的 Linux 环境构建，扩展加载能力不可用（仅跳过，不报错）。
