# 词库开发流程

开发一个词库（机器人 `.n` / 接口 `.n` / 网页 `.wn`）通常按下面顺序推进：定位与读取现状 → 设计改动 → 编写 → 编译检查 → 运行验证 → 收尾。每一步都要真正跑通，不能只停留在「代码看起来对」。

## 一、先分清词库类型

| 类型 | 后缀 | 位置 | 执行入口 |
| --- | --- | --- | --- |
| 机器人词库 | `.n` | `<账号路径>/dic/` | 靠用户消息匹配触发词 |
| 接口词库（被 HTTP 访问） | `.n` | 网站根目录（public/ 等） | 只有 `Main` |
| 网页词库 | `.wn` | 网站根目录 | 无触发词，页面里的执行块自动执行 |

三类的取舍规则见「触发词与取值」，各自的开发规范见「机器人词库开发」「API 词库开发」「网页词库开发」；通用语法见「词库语法」各篇。

## 二、读取现状

1. 修改前先读取目标文件的最新完整内容，再在其基础上改动；写入是全文覆盖，不要凭记忆拼片段；
2. 只改目标文件，不要顺手新建同类文件；确实要新建时按用户要的类型与落点建。

## 三、设计改动

1. 先想清楚要新增 / 修改哪些词条、触发词叫什么、用到哪些变量与内置函数，再动手写；
2. 触发词按词库类型取舍（见「触发词与取值」）；
3. 不确定的内置函数、对象方法或参数用法，先查内置文档求证，不要猜、也不要往词库里写 `u1` / `xxx1` 之类试探词条——既不生效，还会污染词库。

## 四、编写

1. 词条边界是硬约束：触发词独占一行，其上方必须有一个空行与头部或上一条词条分隔（空行是词条的硬边界）；完整规则见「文件结构」「注释与换行」；
2. 网页词库的执行块写法见「网页词库语法」。

## 五、编译检查与修复

保存 `.n` 会重新编译并返回诊断：error 级说明词库跑不起来，必须逐条修复后再次保存，直到 error 级清零；本轮改动引入的 warning 也应一并修掉。

## 六、运行验证

改完要实际运行，不能只凭编译通过就认为完成：

1. 机器人词库靠用户消息匹配触发词，需要用户发消息才能唤起，应在说明里写清该发送哪条触发词；属于「一次性脚本」「画图 / 计算结果」这类改完就要看效果的，把触发词写成 `Main` 便于直接运行；
2. 接口词库被 HTTP 访问时只会执行 `Main`，自己验证时也以 `Main` 触发；
3. 网页词库在词库调试页运行会顺序执行页面里的执行块并完成模板渲染，据此确认执行块已消失、内联块只剩其输出、`{{.键}}` 已被真实数据替换；渲染为空或模板键没被替换时，先核对 id / 变量名。

## 七、收尾

1. 说明改了哪个文件、新增 / 修改了哪些词条、本轮编译诊断结果（几个错误 / 几条警告、是否已清零）与运行结果；
2. 验证用的临时测试词条（如 `测试` / `test`）与临时文件用完立即清掉，不要留在用户的词库里；确实需要保留的，先说明用途。
