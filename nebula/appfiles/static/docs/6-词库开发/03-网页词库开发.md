# 网页词库开发

网页词库（WebNebula，后缀 `.wn`）是「HTML 容器 + 内嵌执行块」的网页：被访问时由服务端执行块生成内容，最后整份 HTML 用 Go 模板渲染一次并作为响应返回。语法细节（两种执行块、执行顺序、模板渲染、HTTP 请求响应、完整示例）见「词库语法 / 网页词库语法」篇，这里只讲开发与验证要点。

## 一、文件与位置

1. `.wn` 默认放在网站根目录（`public/`）下，访问路径即文件路径：`public/index.wn` ↔ `/index.wn`（默认首页）、`public/about.wn` ↔ `/about.wn`；
2. 请求由 `system/router.n` 路由：命中 `.wn` 时先 `$设置头部 Content-Type text/html;charset=UTF-8$` 再 `$执行网页词库文件 <路径>$`；文件不存在时输出 `public/404.wn`。

## 二、写执行块

1. 页面里写服务端 Nebula 脚本（不是 JavaScript），推荐用 `<?n ... ?>` 内联块就地输出，大段多行脚本用 `<script type="nebula">` 脚本块；
2. `.wn` 没有触发词：不要写 `Main`、也不要用 `%参数N%`（那是机器人消息匹配用的）；
3. 块里禁止写 JavaScript（`let` / `document` / `console` / 箭头函数等），写了不会执行；需要浏览器端交互 / 动画时另写一个不带 `type` 的普通 `<script>`，让浏览器运行；
4. 页面里重复出现的 HTML（列表项、表格行、卡片、下拉选项等）不要按份数复制粘贴，改用 `<?n` 内联块配合循环框（`循环>i=次数`，闭合行写 `<循环`）或遍历框（`遍历>键,值=数据`，闭合行写 `<遍历`）就地生成。

## 三、取值与输出

1. 内联块就地输出即可；需要把值放到页面别处、或在普通 `<script>`（JS）里用时，才在脚本块里赋值、页面用 `{{.键}}` 取；
2. 模板键写错不会报错、只会渲染成空——页面出现大片空白时先核对 id / 变量名；
3. 需要把拼出来的 HTML 真正当标签插进页面时，用「HTML 组件」（`$创建HTML$` 建对象、`$对象.设置*$` 拼结构、`$对象.获取$` 取结果），再就地输出以绕开模板转义，用法见「内置函数 / HTML 组件」篇。

## 四、与机器人 / 接口词库的边界

1. `.wn` 不能承载机器人功能：机器人只执行 `<账号路径>/dic/` 下的 `.n`，用户发消息不会触发 `.wn`；
2. 需要 JSON / 纯文本接口时改用被 HTTP 访问的 `.n`（以 `Main` 为触发词），不要用 `.wn` 硬凑，见「API 词库开发」。

## 五、开发与验证

1. 编辑器保存时会按 HTML 结构自动缩进，两种执行块的行首缩进在解析前都会被裁掉；确实要保留行首空白时（如文本框内容带缩进），用 `//@关闭缩进` 与 `//@启用缩进` 把这几行夹起来；
2. 保存 `.wn` 会对执行块做变量检查与模板键核对并给出 warning（「变量赋值后未被使用」= 死代码、「模板键不存在」= 页面渲染成空），有 warning 应逐条修掉；
3. 在词库调试页运行 `.wn` 会返回渲染完成的整页 HTML，据此确认执行块已消失（脚本块整块没了、内联块只剩其输出）、`{{.键}}` 已被真实数据替换；渲染空白或模板键没被替换时，先核对 id / 变量名再重新保存与运行。
